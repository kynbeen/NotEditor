# 독립 PDF 페이지 조합기

**날짜:** 2026-08-25
**상태:** 구현 완료

## 왜 하는가

여러 PDF에서 필요한 페이지만 골라 하나로 합치는 작업은 기존 편집기에서 반복하기 번거롭다. 페이지를
이미지로 변환해 다시 PDF로 만드는 도구는 텍스트 검색, 벡터 도형, 링크, 주석과 양식 같은 원본 정보를
잃기 쉽고, 파일별 선택 결과와 최종 순서를 한 화면에서 확인하기도 어렵다. 다른 프로젝트에 종속되지
않는 전용 도구로 이 작업을 빠르고 안전하게 끝낼 필요가 있다.

## 목표

Windows에서 터미널 없이 실행되는 독립 데스크톱 앱을 만든다. 사용자는 여러 PDF를 추가하고 각 문서의
페이지를 썸네일 또는 범위 입력으로 선택한 뒤, 선택 페이지를 자유롭게 재정렬하고 원본·최종 결과를
미리 본 다음 하나의 PDF로 저장한다. 미리보기만 래스터 이미지로 만들고 최종 PDF는 원본 페이지 객체를
구조적으로 복사해 정보 손실을 최소화한다.

## 성공 기준

- [x] 독립된 `PDF 페이지 조합기` 창과 실행 경로가 있으며 터미널이 나타나지 않는다.
- [x] 파일 선택 창으로 PDF를 제한 없이 여러 개 추가할 수 있고 추가 순서가 문서 목록에 유지된다.
- [x] 각 PDF의 이름, 페이지 수, 페이지별 썸네일과 확대 미리보기를 볼 수 있다.
- [x] `1-3, 5, 8-10` 형식의 범위 입력과 페이지 썸네일 클릭을 모두 지원하며 잘못된 범위는 명확히 알린다.
- [x] 선택 페이지는 밝게, 선택하지 않은 페이지는 어둡게 표시되어 상태를 즉시 구분할 수 있다.
- [x] 기본 결과 순서는 PDF 추가 순서와 각 PDF 내부 페이지 번호순이다.
- [x] 선택된 개별 페이지를 드래그 앤 드롭해 최종 결과 순서를 자유롭게 바꿀 수 있다.
- [x] 결과 목록의 각 페이지 썸네일과 확대 미리보기로 저장 전 최종 순서를 확인할 수 있다.
- [x] 선택하지 않은 페이지는 결과에 없고, 선택·재정렬한 순서와 출력 PDF의 실제 페이지 순서가 일치한다.
- [x] 최종 PDF의 선택 페이지는 원본 페이지 크기, 회전, 텍스트, 벡터, 이미지, 외부 링크, 주석과
  대화형 양식 위젯을 가능한 범위에서 유지하며 페이지 전체를 이미지로 다시 만들지 않는다.
- [x] 선택된 페이지 사이의 유효한 내부 링크·named destination은 가능한 범위에서 유지하고,
  제외된 페이지를 가리키는 링크·책갈피는 깨진 참조로 남기지 않는다.
- [x] 양식 필드 이름 충돌은 자동으로 안전하게 바꾸며 부분 양식 트리 등 완전 보존이 불가능한 경우
  저장 결과와 함께 경고한다.
- [x] 암호화·잠금 PDF는 첫 버전에서 열지 않고 파일별로 명확한 오류를 표시한다.
- [x] 네이티브 다른 이름으로 저장 창을 사용하며 작업 원본을 수정하지 않는다.
- [x] 앱 종료 시 원본 복사본·썸네일·결과 미리보기 등 임시 자료가 자동 삭제된다.
- [x] 서로 다른 페이지 크기·회전·텍스트·벡터·이미지·링크·주석·양식을 포함한 테스트 PDF로 구조와
  전 페이지 렌더를 검증한다.
- [x] UI는 넓은 3단 구성, 일관된 여백·타이포그래피·상태색과 반응형 최소 폭을 갖춘다.

## 범위 밖

- PDF 본문 텍스트·이미지·주석을 새로 작성하거나 지우는 일반 편집 기능
- OCR, 페이지 회전·자르기, 워터마크, 압축, 서명 추가
- 암호 해제, DRM 우회, 첫 버전의 암호 입력 지원
- 작업 이력, 원본 PDF, 썸네일 또는 결과 PDF의 앱 내부 영구 보관
- 페이지 구성이 바뀐 뒤 기존 디지털 서명의 유효성을 유지한다고 보장하는 것
- macOS·Linux 패키징과 모바일 앱

## 제약

- 다른 프로젝트의 파이프라인·체크포인트·입출력 폴더와 상태를 공유하지 않는 독립 저장소다.
- 앱은 원본 PDF를 읽기 전용으로 열고 사용자가 선택한 새 경로에만 결과를 쓴다.
- 미리보기는 PNG로 렌더할 수 있지만 최종 PDF 페이지 내용은 래스터화하지 않는다.
- PDF 구조 복사는 form-aware page copy를 지원하는 pikepdf/qpdf 계층을 우선하고, PyMuPDF는 페이지
  판독과 미리보기 렌더에 사용한다.
- 페이지 재정렬은 객체 identity를 유지하는 이동 방식으로 구현해 내부 참조를 불필요하게 끊지 않는다.
- PDF 문서 전체에 하나만 존재할 수 있는 metadata·outline·첨부 파일·서명은 여러 원본을 단순 합산할 수
  없다. 선택 페이지에 직접 연결된 구조를 우선 보존하고, 불가능하거나 의미가 바뀌는 항목은 경고한다.
- Windows 백그라운드 프로세스는 `pythonw.exe` 또는 `CREATE_NO_WINDOW`로 실행한다.
- 임시 파일은 운영체제 임시 디렉터리의 앱 전용 세션 폴더에만 만들고 정상 종료 시 제거한다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 기존 애플리케이션 저장소에 기능 통합 | 사용자가 별도 저장소와 독립 프로그램을 요구했다. |
| PDF 페이지를 PNG/JPEG로 변환한 뒤 다시 PDF 생성 | 텍스트 검색·벡터·링크·주석·양식과 원본 해상도를 잃어 정보 손실 최소화 요구에 어긋난다. |
| 최종 순서를 PDF 추가 순서로만 고정 | 사용자가 개별 선택 페이지의 자유로운 드래그 재정렬을 선택했다. |
| 작업과 결과를 앱 폴더에 자동 보관 | 사용자가 임시 처리 후 결과만 직접 저장하고 캐시는 삭제하는 방식을 선택했다. |
| 첫 버전부터 암호 입력 지원 | 잠금 권한·저장 권한과 실패 UX까지 범위가 크게 늘어나므로 명확한 오류를 우선한다. |
| Tkinter 위젯만으로 UI 구성 | 다량의 썸네일, 3단 반응형 레이아웃과 부드러운 drag-and-drop을 미려하게 구현하기 어렵다. |
| Electron/Tauri 별도 프런트 빌드 체인 도입 | Python과 중복되는 대형 도구 체인이 생긴다. Windows WebView2 기반 pywebview면 충분하다. |

## 열린 질문

구현을 막는 열린 질문은 없다. 앱 이름은 기능이 바로 드러나는 `PDF 페이지 조합기`를 기본으로 사용한다.
