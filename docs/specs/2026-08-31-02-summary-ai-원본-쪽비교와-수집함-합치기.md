# summary.ai 원본 쪽 비교 · 수집함 합치기

**날짜:** 2026-08-31
**상태:** 완료

## 왜 하는가

NotEditor는 summary.ai가 파일과 쪽 범위를 모두 정한 판 1 합치기 계획만 열 수 있다. 그래서
summary.ai의 첫 `합치기` 버튼은 NotEditor를 바로 띄우지 못하고 별도 파일 선택 단계를 먼저 둔다.
또한 필기 옮기기에는 두 PDF의 같은 쪽·다른 쪽을 보여 주는 매칭 UI가 있지만 일반 PDF 원본
동일성을 검사하는 독립 기능과 summary.ai 인계가 없다.

## 목표

summary.ai가 수집함 시작 경로만 지정해도 NotEditor가 즉시 열려 파일을 고르고 합칠 수 있게 한다.
원본 갱신 검토에서는 실제 사용한 번들 PDF를 기준 문서로, 현재 수집함 PDF들을 대상 문서로 열어
같은 쪽과 다른 쪽을 두 열로 표시하고, 대상 쪽을 문서 합치기와 같은 방식으로 선택해 전체
갱신, 합쳐서 갱신 또는 넘어가기 결정을 summary.ai에 돌려준다.

## 성공 기준

- [x] 공용 인계 계약의 새 판을 검증하며 판 1 합치기 계획도 계속 읽는다.
- [x] 빈 합치기 계획은 허용하고 지정된 `input_root`에서 PDF 다중 선택 대화상자를 자동으로 연다.
- [x] `input_root` 밖에서 고른 파일은 summary.ai 인계 세션에서 저장 전에 거부한다.
- [x] 비교 계획은 기준 PDF 한 개와 현재 PDF 한 개 이상을 경로로 받는다.
- [x] 기준 PDF와 모든 현재 PDF의 쪽 지문을 비교해 같은 쪽, 한쪽 전용 쪽, 불확실한 대응을 낸다.
- [x] 비교 화면은 필기 옮기기의 `review-row`, 확인 강조, 두 열 쪽 미리보기 패턴을 재사용한다.
- [x] 현재 PDF 쪽은 선택 표시·전체/해제·범위 선택을 제공하고 결과 순서는 문서·쪽 순서를 따른다.
- [x] 비합치기 검토는 전체 갱신과 넘어가기만, 합치기 검토는 합쳐서 갱신과 넘어가기만 노출한다.
- [x] 전체 갱신·넘어가기는 결정 사이드카를, 합쳐서 갱신은 결과 PDF·합치기 사이드카와 결정을
      PDF 완료 후 원자적으로 기록한다.
- [x] 사용자가 닫거나 취소하면 summary.ai 번들과 확인 기준은 바뀌지 않는다.
- [x] 데스크톱 체크아웃·패키지 실행에서 `--open-plan`으로 비교와 빈 합치기 계획이 모두 열린다.
- [x] 쪽 매칭, 경로 제한, 결정 기록, 기존 합치기·필기 옮기기 회귀 테스트가 통과한다.

## 범위 밖

- 전사본 TXT 비교 또는 합치기
- Drive 경로 직접 열기나 Drive 파일 수정
- summary.ai 체크포인트 또는 번들 파일을 NotEditor가 직접 수정하는 동작
- 일반 웹 배포에서 로컬 절대경로 인계 지원

## 제약

- summary.ai 인계는 데스크톱 로컬 실행에서만 처리한다. 웹 업로드 경로와 섞으면 임의 로컬 경로를
  서버가 읽는 계약이 된다.
- 합치기 결과와 실제 화면 순서의 단일 책임은 NotEditor에 둔다.
- 기준 문서는 비교 전용이며 합치기 결과의 선택 대상이 될 수 없다.
- 수동 결과 순서변경은 제공하지 않고, 문서를 추가한 순서와 각 PDF의 원래 쪽 순서를 사용한다.
- 쪽 동일성은 기존 `page_match`의 시각 지문·동적 정렬 기준을 재사용하고, 파일 바이트 해시만으로
  쪽 내용을 같다고 판정하지 않는다.
- 경로와 결정 파일 규격은 workspace의 공용 계약을 단일 원본으로 한다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| summary.ai가 쪽 이미지를 렌더해 자체 비교 | 동일성 엔진과 필기 옮기기 UI를 양쪽에 중복시킨다. |
| 기존 합치기 계획에 기준 PDF를 일반 `parts`로 추가 | 기준 쪽이 실수로 결과 PDF에 포함될 수 있고 역할 경계가 사라진다. |
| 원본별로 비교 창을 여러 번 열기 | 합친 결과와 여러 최신 대상의 관계 및 최종 페이지 선택 순서를 한눈에 볼 수 없다. |
| 비교 결과가 같으면 자동 넘어가기 | 사용자가 의도한 수정 여부를 시스템이 대신 결정하며, 불확실 매칭을 숨긴다. |
| 드래그로 결과 순서 변경 | 순서 조작 UI와 상태가 검토 작업을 복잡하게 하므로 문서·쪽 순서로 고정했다. |

## 열린 질문

없음. summary.ai가 인계한 생성 방식에 따라 허용 결정을 제한한다.

## 변경 이력

- 2026-08-31: 최초 작성. 빈 합치기, 수집함 시작 경로, 다중 문서 쪽 비교와 결정 인계를 확정했다.
- 2026-08-31: 구현과 소스 체크아웃 검증 완료. 전체 회귀 테스트, 판 2 교차 저장소 결정 왕복,
  소스 체크아웃의 실제 빈 합치기 `--open-plan` 실행을 확인했다. 최신 코드 패키지 재빌드 검증은 남았다.
- 2026-08-31: 패키지 검증 완료로 명세를 닫았다. 최신 코드로 PyInstaller 패키지를 다시 빌드하고,
  체크아웃에서는 실제 프런트엔드로 review 계획을 열어 두 열 비교 행·생성 방식별 갱신 버튼·기준
  문서 제외를 확인했으며(부분집합 대조에서 41쪽 동일·46쪽 현재 전용·사용본 전용 0쪽), 패키지
  실행본에서는 review 계획이 계획 제목까지 반영해 열리고 빈 합치기 계획이 파일 선택 대화상자를
  자동으로 여는 것을 확인했다. 전체 189개 테스트도 다시 통과했다.
- 2026-08-31: 원본 검토를 큰 왼쪽 비교와 오른쪽 쪽 선택으로 재배치하고, 선택 해제 쪽을 비교
  미리보기에서도 어둡게 표시했다. 일반 합치기와 원본 검토의 수동 결과 순서변경은 제거했다.
