# summary.ai 합치기 인계 계약 판 1

**날짜:** 2026-08-31
**상태:** 진행 중
**단일 원본:** `../workspace/docs/contracts/summary-ai↔noteditor-합치기.md`

## 왜 하는가

summary.ai는 여러 원본 PDF에서 고른 쪽을 NotEditor로 합친 뒤 그 결과와 합치기 방법을 함께
기록한다. 원본이 나중에 바뀌면 기록된 쪽 번호가 더는 같은 내용을 가리킨다고 보장할 수 없으므로,
summary.ai가 자동으로 다시 합치지 않고 원본·쪽 선택·순서를 미리 채운 NotEditor를 열어 사용자가
눈으로 확인해야 한다.

summary.ai 쪽 계획 작성, 실행기 탐색, 결과 감시와 반영은 이미 구현됐다. 현재 NotEditor는
`--open-plan`을 알지 못해 조용히 종료하고, 결과 옆에 합치기 방법도 남기지 않아 연동이 끝나지
않는다.

## 목표

workspace 계약 판 1을 NotEditor 데스크톱 실행 경로에 구현한다. 전달받은 계획을 검증한 뒤 원본과
쪽 선택·결과 순서를 화면에 적용하고, 사용자가 확인·수정해 저장하면 지정된 결과 PDF를 먼저 쓴 뒤
실제로 저장된 상태를 `<결과>.merge.json` 사이드카로 원자적으로 기록한다.

## 성공 기준

- [ ] `python -m noteditor --open-plan <handoff.json>`과 패키지 `NotEditor.exe --open-plan ...`이
  같은 계약으로 실행되며 기존 `--debug` 및 인자 없는 실행은 유지된다.
- [ ] 계약 판 번호, 계획 파일·출력 경로, 비어 있지 않은 parts, PDF 경로와 페이지 범위를 검증하고
  모르는 판이나 잘못된 계획을 조용히 추측하지 않고 사용자에게 오류로 알린다.
- [ ] `ComposerApi.startup_plan()`이 각 절대경로 PDF를 한 번씩 등록하고, 실행 때 새로 생긴
  `document_id`로 계획의 선택 쪽과 parts 순서를 결과 순서에 정확히 매핑한다. 빈 pages는 해당
  파일 전체를 뜻한다.
- [ ] 프런트는 시작 계획의 문서·선택·결과 순서·제목을 첫 화면에 적용하고, 일반 데스크톱과 웹
  실행에는 빈 계획을 반환해 기존 초기 상태를 유지한다.
- [ ] 계획에 `output_path`가 있으면 저장 대화상자를 띄우지 않고 정확히 그 경로에 PDF를 저장한다.
  원본이나 대상 파일을 덮어쓰지 않으며 결과는 항상 별도 파일이다.
- [ ] PDF 저장 성공 뒤에만 `<결과이름>.merge.json`을 기록한다. 사이드카는 계약 판, NotEditor
  버전, 절대 output, UTC saved_at과 사용자가 실제 저장한 parts 경로·압축 페이지 범위를 담는다.
- [ ] 화면 순서를 계약의 parts로 손실 없이 표현할 수 없는 수동 편집은 거짓 사이드카를 쓰지 않고
  저장 전에 명시적으로 거부한다.
- [ ] NotEditor 단위·정적 UI·전체 회귀 테스트, summary.ai의 연동 계약 테스트, 실제 handoff →
  NotEditor 저장 → PDF·사이드카 회수 왕복 검사가 통과한다.
- [ ] summary.ai와 workspace 저장소는 읽기 전용으로 유지하고 NotEditor만 수정한다.

## 제약

- 계약 단일 원본의 `version: 1`과 필드 의미를 독자적으로 바꾸지 않는다. 변경이 필요하면 먼저
  workspace 계약 판을 올리고 양쪽을 함께 맞춰야 한다.
- `document_id`는 세션 난수이므로 handoff나 사이드카에 저장하지 않는다. 경로와 페이지 범위만
  경계를 건넌다.
- PDF를 먼저 원자적으로 저장하고 사이드카를 나중에 원자적으로 교체한다. summary.ai는 둘이 모두
  있을 때만 완료로 판정한다.
- summary.ai에서 합치기를 다시 구현하거나 원본 변경을 자동 승인하지 않는다. 결과 바이트와 선택
  의미의 단일 책임은 NotEditor와 사용자 확인에 둔다.
- 기존 로컬 웹 실행기·원격 웹·Docker에는 `--open-plan` 파일 시스템 계약을 노출하지 않는다.
  연동은 로컬 데스크톱 앱 전용이다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| summary.ai가 기록된 범위로 자동 재합치기 | 원본 앞쪽 변경으로 같은 번호가 다른 내용을 가리킬 수 있어 사람이 봐야 한다. |
| summary.ai 안에 별도 PDF 합치기 구현 | NotEditor와 결과 바이트가 달라져 재현 해시 비교가 영원히 깨진다. |
| 세션 `document_id`를 handoff에 기록 | 실행할 때마다 바뀌는 난수라 다음 세션에서 사용할 수 없다. |
| 계획 출력도 저장 대화상자로 다시 묻기 | summary.ai가 감시하는 약속 경로에 결과가 나타나지 않아 세션이 끝나지 않는다. |
| PDF보다 사이드카를 먼저 기록 | summary.ai가 반쯤 쓰인 결과를 완료로 집어 갈 수 있다. |
| 표현할 수 없는 페이지 순서를 적당히 정렬해 기록 | 화면에서 저장한 결과와 사이드카가 달라져 이후 재현·변경 추적의 근거가 사라진다. |

## 변경 이력

- 2026-08-31: summary.ai 최신 핸드오프와 workspace 계약 판 1을 읽어 NotEditor의 세 가지 미구현
  항목(`--open-plan`, `startup_plan()`, 저장 사이드카)을 현재 목표에 추가했다.
