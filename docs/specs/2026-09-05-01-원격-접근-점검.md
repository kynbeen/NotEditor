# 원격 접근 점검 — 통합 아키텍처에서 이 리포가 할 일은 거의 없다

**날짜:** 2026-09-05
**상태:** 점검 완료 / 신규 공사 없음
**상위 그림:** [`workspace/docs/architecture/학습도구-통합-아키텍처.md`](../../../workspace/docs/architecture/학습도구-통합-아키텍처.md)
**단계:** 통합 아키텍처 1단계(접근 계층) 중 이 리포 몫

## 왜 이 문서가 짧은가

노트북을 서버로 두고 폰·태블릿을 프론트엔드로 쓰기로 하면서 4리포의 서버 준비 상태를 확인했다.
**이 리포는 이미 준비돼 있다.** 없는 일을 만들지 않기 위해, 확인한 것과 확인하지 않은 것만
기록하고 닫는다.

## 확인한 것

| 항목 | 상태 |
|---|---|
| 바인딩 | [`web.py:503`](../../noteditor/web.py) 이 이미 `NOTEDITOR_HOST` 기본값 `0.0.0.0` |
| 배포 형태 | Docker + [`render.yaml`](../../render.yaml). 처음부터 **여러 기기에서 열 것을 전제**로 만들어졌다 |
| 세션 격리 | 쿠키 토큰별 `ComposerApi` 와 임시 디렉터리 ([`web.py:66-81`](../../noteditor/web.py)). 남의 작업공간을 읽을 경로가 없다 |
| 자원 한도 | `MAX_SESSIONS=200`, `SESSION_TTL`, 업로드 상한, 주기적 청소 ([`web.py:41-45`](../../noteditor/web.py)) |
| 프록시 대응 | `proxy_headers=True` |

## 판정 — 인증을 새로 넣지 않는다

세션 쿠키는 **작업 격리용이지 인증이 아니다.** 토큰 없이 접속한 누구에게나 새 세션이 발급된다
([`web.py:78`](../../noteditor/web.py)).

그럼에도 rag-chat·summary.ai 와 위험 등급이 다르다:

- **이 리포는 족보를 보관하지 않는다.** 사용자가 그때 올린 PDF 만 다루고 TTL 뒤 지운다.
  rag-chat 은 `99_SECRET_GUIDE_*.md` 를 색인해 두고 있고, summary.ai 대시보드는 과목 구조와
  파일 경로를 그대로 보여 준다 — 그쪽은 노출 자체가 유출이다.
- **Tailscale 안에서만 열면 접속 경로가 내 기기로 한정된다.** 그 위에 인증을 더 얹는 것은
  보관 자산이 있는 쪽부터 할 일이다.

따라서 이 리포는 **바인딩 주소만 Tailscale 로 좁히는 것으로 충분하다.** 코드 변경 없이
`NOTEDITOR_HOST` 환경변수로 된다.

## 지켜야 할 것

- **`0.0.0.0` 을 기본값으로 그냥 두고 노트북에서 띄우지 않는다.** 카페·학교 와이파이에서
  같은 망의 누구에게나 열린다. 노트북에서 띄울 때는 `NOTEDITOR_HOST` 를 Tailscale 주소
  (`100.x.y.z`)로 지정한다. Render 배포본은 이 제약과 무관하다
- summary.ai 의 `합치기` 동선은 **데스크톱 앱을 띄우는 경로**다
  (합치기 인계 규격 — `workspace/docs/contracts/summary-ai↔noteditor-합치기.md`).
  원격에서 성립하지 않으므로 이번 아키텍처의 대상이 아니다

## 확인하지 않은 것 (열린 질문)

1. **Render 배포본이 지금 실제로 살아 있는지.** `render.yaml` 이 있다는 것과 배포돼 있다는
   것은 다르다. 살아 있다면 그것은 이미 인터넷에 공개된 인스턴스이므로, Tailscale 논의와
   별개로 업로드 상한·세션 수 설정이 현재 값으로 적절한지 한 번 봐야 한다
2. 태블릿 브라우저에서 쪽 선택·드래그 UI 가 실제로 쓸 만한지 — 실기 확인 전이다
