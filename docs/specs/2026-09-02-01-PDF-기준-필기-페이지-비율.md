# PDF 기준 필기 페이지 비율

**날짜:** 2026-09-02
**상태:** 구현 완료, 실기 왕복 검증 대기

## 왜 하는가

현재 본문 정렬 경로는 새 PDF를 원본 필기 문서의 페이지 캔버스 안에 다시 그린다. 새 PDF와
원본의 페이지 비율이 다르면 캔버스 밖으로 나간 위·아래 또는 좌·우가 잘리고, 결과 문서도 새
PDF가 아니라 원본 문서의 페이지 비율을 따른다. 같은 조건에서 Notewise와 Goodnotes 결과는 웹에서
다운로드까지 도달하지 못한다는 실사용 보고도 있다.

## 목표

Samsung Notes, Notewise, Goodnotes 6의 편집 가능한 필기를 본문 기준으로 같은 위치에 옮기는 기존
기능을 유지하면서, 대상 PDF가 있는 모든 결과 쪽의 크기와 비율을 대상 PDF 기준으로 만든다. 대상
PDF의 쪽과 가시 영역은 하나도 누락하거나 잘라내지 않고, 세 형식 모두 결과 파일을 저장·다운로드할
수 있게 한다.

## 성공 기준

- [x] 대상 PDF와 원본 필기 문서의 페이지 비율이 달라도 대상 PDF의 모든 쪽이 결과에 한 번씩 들어간다.
- [x] 대상 PDF에 대응하는 결과 쪽은 대상 PDF의 페이지 크기·비율·회전을 따른다.
- [x] 비율 차이로 늘어난 위·아래 또는 좌·우 영역이 결과에서 잘리지 않는다.
- [x] 기존 본문 기준 정렬을 적용해 필기가 대상 PDF 본문의 같은 위치에 놓인다.
- [ ] Samsung Notes의 필기·형광펜과 포맷 무결성, Notewise의 알 수 없는 페이지 객체,
  Goodnotes의 펜 종류·압력·색·굵기와 편집 가능 데이터를 보존한다.
- [x] 쪽 추가·삭제·재정렬과 원본에만 남은 필기 쪽을 보존하는 기존 행 계획 동작이 유지된다.
- [x] 원본에만 있는 필기 쪽은 대응할 대상 쪽이 없으므로 기존 배경과 기존 페이지 비율로 보존한다.
- [x] 동일 비율의 기존 빠른 경로는 결과와 성능 특성을 유지한다.
- [x] 세 형식의 서로 다른 가로·세로 비율 회귀 테스트와 웹 다운로드 테스트가 통과한다.
- [x] 저장 후 아카이브·페이지 수·PDF 바이트/기하·필기 객체 보존을 다시 읽어 검증한다.
- [ ] 실제 Samsung Notes·Notewise·Goodnotes 앱에서 가능한 포맷은 왕복 확인하고, 이 환경에서 확인할
  수 없는 앱 검증은 미확인으로 명시한다.

## 범위 밖

- 필기 앱의 비공개 파일 형식을 일반 공개 형식으로 바꾸는 기능.
- 페이지마다 서로 다른 비선형 왜곡이나 본문 자체가 재배치된 개정판의 자동 정렬.
- 필기 옮기기와 무관한 문서 합치기 UI 개편.
- 대응할 대상 쪽이 없는 원본 전용 필기 쪽을 임의의 대상 쪽에 합치는 동작.

## 제약

- 원본 필기 파일과 대상 PDF는 수정하거나 덮어쓰지 않는다.
- 대상 쪽을 원본 비율에 맞춰 자르거나 늘려 그리지 않는다. PDF 가시 영역 보존이 최우선이다.
- 필기를 평탄화된 PDF 그림으로 바꾸지 않는다. 앱에서 계속 편집 가능한 원시 필기 데이터를 보존해야
  한다.
- 자동 매칭과 사용자가 확정한 행 계획을 우회하지 않는다. 좌표 수정이 쪽 대응을 바꾸어서는 안 된다.
- Samsung Notes의 ZIP 꼬리표·엔트리 규칙과 각 형식의 ID·색인·참조 무결성을 유지하고 저장 후 검증한다.
- 실제 파일 검증은 `imports/` 또는 테스트용 사본에서만 수행하고 Drive 원본은 읽기 전용으로 둔다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 새 PDF를 계속 원본 캔버스에 맞춰 다시 그리기 | 현재 잘림의 직접 원인이며 대상 PDF 비율을 보존하지 못한다. |
| 대상 PDF를 원본 비율로 늘이거나 찌그러뜨리기 | 영역은 남아도 PDF와 필기 모양이 왜곡된다. |
| 필기를 PNG로 렌더링해 PDF에 합치기 | 편집 가능한 펜·형광펜 데이터와 도구 속성을 잃는다. |
| 대상에 없는 원본 필기 쪽을 버리기 | 기존의 무손실 행 계획 계약을 깨고 사용자 필기를 누락한다. |
| 세 형식 중 한 형식만 예외 처리하기 | 원인이 공통 페이지 기하 계약에 있고, 나머지 형식의 다운로드 실패를 남긴다. |

## 열린 질문

- 실제 앱 왕복 검증에 사용할 비율 차이 실물 샘플은 현재 저장소에 없다. 합성 회귀 검사 뒤 사용자가
  제공하는 `imports/` 사본으로 기기별 확인이 필요하다.
- Goodnotes 6는 저장 결과 자체의 앱 왕복이 아직 미확인인 실험 기능이다.

## 변경 이력

- 2026-09-02: 실사용 보고와 기존 정렬 구현을 대조해 PDF 기준 기하·무누락·세 형식 저장을 범위로 확정했다.
- 2026-09-02: 세 형식의 캔버스 역변환과 저장 후 검증을 구현하고 전체 234개 검사를 통과했다. 실제 앱 왕복은 미확인으로 남겼다.
