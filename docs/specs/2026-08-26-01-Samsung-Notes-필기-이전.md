# Samsung Notes 필기 이전

**날짜:** 2026-08-26  
**상태:** 1차 구현 완료

## 목표

Samsung Notes에서 PDF 위에 작성한 필기·형광펜이 들어 있는 `.sdocx`와 새 배경 `.pdf`를 받아,
편집 가능한 Samsung 펜 데이터를 같은 페이지의 같은 위치에 유지한 새 `.sdocx`를 만든다. 원본 두
파일은 수정하지 않고 일반 사용자는 앱의 `필기 옮기기` 창에서 파일 선택과 저장만 수행한다.

## 입력과 출력

- 입력 1: 가져온 PDF 배경 하나와 필기·형광펜을 포함한 Samsung Notes `.sdocx`
- 입력 2: 필기를 받을 대상 `.pdf`
- 출력: 입력 1의 필기 객체와 입력 2의 PDF 배경을 가진 새 `.sdocx`

## 성공 기준

- [x] SDOCX ZIP과 `media/mediaInfo.dat`를 검증해 내장 PDF bind id·파일명·SHA-256 위치를 찾는다.
- [x] 내장 PDF와 대상 PDF의 페이지 수, 각 페이지 크기와 회전이 모두 같은지 확인한다.
- [x] 대상 PDF 바이트와 `mediaInfo.dat`의 SHA-256만 교체한다.
- [x] `.page`, `.spi`, `note.note`, `pageIdInfo.dat`, `end_tag.bin` 등 필기 관련 엔트리를 바이트 단위로 보존한다.
- [x] EOCD 뒤의 148바이트 Samsung 꼬리표와 각 엔트리의 헤더·순서·압축 바이트를 그대로 보존한다.
- [x] 임시 파일에 먼저 기록하고 ZIP 구조·내장 PDF·해시·꼬리표·보존 엔트리를 다시 검증한 뒤 원자적으로 저장한다.
- [x] 원본 SDOCX나 대상 PDF 경로로는 저장하지 못하게 한다.
- [x] 앱 안에서 SDOCX와 PDF를 고르고 호환성·페이지 수·필기 페이지 수를 확인한 뒤 저장할 수 있다.
- [x] 암호화·손상·다중 내장 PDF·페이지 좌표 불일치는 명확한 오류로 거부한다.

## 2차 목표 — 비율이 달라진 PDF (2026-08-26 추가)

배율이나 여백이 달라진 새 PDF로도 필기를 옮긴다. 기준은 페이지가 아니라 **본문**이다. 세 케이스
(동일 비율 확대/축소, 여백만 증가, 둘 다)는 모두 하나의 상사변환 `x' = s·x + t` 이므로 따로 다루지
않는다.

- [x] 두 문서의 본문 영역을 자동으로 찾아 문서 전체에 쓸 배율 `s`와 이동 `t`를 하나만 추정한다.
- [x] 필기 좌표는 건드리지 않는다. 대신 새 PDF를 **원본 페이지 크기의 캔버스에 다시 그려** 넣는다.
- [x] 가로세로 비율이 다르면 폭을 기준으로 맞추고 세로 오차를 mm로 경고한다.
- [x] 페이지 크기가 같고 본문 배치도 그대로면 사용자의 PDF를 바이트 그대로 넣는다(기존 경로 유지).
- [x] 저장 전에 옛 배경과 새 배경을 겹쳐 보는 미리보기로 사람이 확인한다.

### 왜 필기가 아니라 배경을 옮기는가

`.page`는 캔버스 좌표(예: 1848×1039)에 필기 획을 저장하고, 배경 PDF는 `pdfDataList = (fileId,
pageIndex, rect)` 라는 **페이지 속성**으로 그 캔버스의 사각형에 그려진다. 즉 필기와 배경은 별개
좌표계로 얹혀 있어서, 배경 쪽만 옮겨도 상대 위치가 맞는다. 실제 샘플에서 캔버스 1848×1039 = PDF
960×540 × 1.925 로 확인했다.

필기 좌표를 다시 쓰는 길은 접었다. 획의 점이 가변길이 델타로 패킹되어 있어 `.page` 전체를 다시
직렬화해야 하고, 참고한 역공학 문서도 stroke width/material 알고리즘은 미확정이라고 적고 있다.
방금 확보한 바이트 보존 성질까지 잃는다. 대신 `pdfDataList`의 rect를 16바이트만 패치하는 길이
남아 있다 — 결과 문서를 새 PDF의 실제 페이지 크기로 만들고 싶어질 때의 다음 단계다.

### 본문 영역을 찾는 방법

페이지를 회색으로 렌더링해 배경색과 다른 픽셀의 경계 상자를 본문으로 본다. 벡터 객체를 세는 것보다
스캔 PDF와 배경색이 있는 문서까지 같은 코드로 다룰 수 있다. 최대 12쪽을 표본으로 삼고 배율·이동은
**중앙값**으로 정한다 — 쪽마다 따로 맞추면 내용량 차이 때문에 쪽마다 어긋난다.

같은 크기의 문서를 잘못 건드리지 않도록 두 조건을 모두 만족할 때만 정렬로 넘어간다.

- 추정한 변환이 '그대로 두기'보다 본문을 실제로 더 잘 맞춘다(잔차가 절반 이하).
- 가로 배율과 세로 배율이 서로 0.5% 안에서 일치한다. 어긋나면 상사변환이 아니므로 본문 배치가
  바뀐 게 아니라 내용이 달라진 것으로 본다.

## 지원 형식 — Notewise 추가 (2026-08-29)

외부 기여(PR #1)로 Notewise `.notewise` 가 두 번째 입력 형식이 됐다. Samsung Notes와 같은
구조 위에 올렸다 — 형식을 가르는 판단은 `noteditor/handwriting_transfer.py` 한 곳에만 있고,
진단·정렬·쪽 매칭은 `noteditor/transfer_plan.py` 를 함께 쓴다.

- `.notewise` 는 ZIP 컨테이너이고, 노트 색인과 각 쪽은 Base64로 감싼 protobuf 메시지다.
  스키마가 공개돼 있지 않으므로 필드 번호와 wire type만으로 훑고, 손대지 않을 필드는 읽은
  바이트를 그대로 되쓴다. 아직 뜻을 모르는 데이터가 저장 과정에서 사라지지 않게 하기 위해서다.
- Samsung Notes와 달리 쪽 추가·삭제 때 아카이브를 다시 만든다. 새 페이지 ID가 필요하기 때문이다.
- **본문 기준 자동 정렬을 지원한다.** 배경 PDF를 원본 페이지 좌표계에 다시 그리는 방식이라
  필기 좌표를 건드리지 않으며, 형식과 무관하다. 크기·여백이 그대로면 사용자의 PDF를 바이트
  하나 바꾸지 않고 넣는다.
- 노트 색인은 Android `Base64.DEFAULT` 표기(76자마다 줄바꿈, 끝에도 줄바꿈)를 지켜야 한다.
  한 줄로 붙이면 일부 버전이 색인을 무시하고 아카이브 순서대로 쪽을 복구해 순서가 뒤섞인다.
- **기존 쪽의 순서 변경은 명시적으로 거부한다.** 순서가 바뀌면 어느 필기가 어느 쪽의 것이었는지
  확신할 수 없다. 조용히 틀린 결과보다 거절이 낫다.
- 펜·형광펜 외의 Notewise 객체는 미리보기에 그리지 않는다. 미리보기에 안 보일 뿐 저장 결과에는
  그대로 남는다. 저장에는 이 해석 결과를 쓰지 않기 때문이다.
- **실제 Notewise 내보내기 파일로는 정렬 경로가 아직 검증되지 않았다.** 기여자가 실물 30쪽
  파일로 확인한 것은 정렬이 없던 시점의 코드다.

## 현재 제약

- 페이지 수와 순서는 같아야 한다. 페이지 자동 대응은 하지 않는다.
- 배율은 문서 전체에 하나만 쓴다. 쪽마다 다른 배치(표지만 다른 문서 등)는 다루지 않는다.
- 결과 문서의 페이지 크기는 원본 SDOCX를 따른다. 새 PDF에서 늘어난 여백은 캔버스 밖으로 잘리며
  잘리는 양을 mm로 알려준다.
- SDOCX 안에 내장 PDF가 정확히 하나인 Samsung Notes 문서만 지원한다.
- Samsung Notes의 비공개 형식을 역공학한 상호운용 기능이며 Samsung의 공식 API를 사용하지 않는다.
- 첫 샘플은 원본 PDF와 대상 PDF가 바이트 단위로 같아서 구조 보존을 검증하기에는 적합하지만,
  실제로 배경 내용이 다른 PDF로 교체되는 화면 검증에는 추가 샘플이 필요하다.
- 결과 파일이 실제로 열리는지는 태블릿의 Samsung Notes에서만 확인할 수 있다. PC에서는 ZIP 구조·
  꼬리표·해시·보존 바이트까지만 검증한다.

## 구현 방식

SDOCX의 `.page`에는 페이지별 PDF bind id·page index와 편집 가능한 펜 객체가 있고, `mediaInfo.dat`는
bind id를 `media/<파일명>`과 SHA-256에 연결한다. 따라서 페이지 좌표계가 같을 때 `.page`를 다시
직렬화할 필요 없이 내장 PDF와 해당 해시만 교체하면 펜 데이터와 위치를 손실 없이 유지할 수 있다.
`.spi`는 Samsung의 렌더 캐시이므로 원본 그대로 보존한다. 내장 PDF의 크기·파일명은 `mediaInfo.dat`
바깥 어디에도 기록되지 않으므로 바이트와 해시만 갈아 끼우면 된다.

**SDOCX는 순수한 ZIP이 아니다.** 파일 끝, ZIP 종료 기록(EOCD) *뒤에* `Document for S-Pen SDK`로
끝나는 148바이트 꼬리표가 붙어 있고 이것은 ZIP 안의 `end_tag.bin`과 타임스탬프 두 개만 다른
사본이다. 또 각 엔트리는 Samsung이 쓴 플래그 비트(`0x0806`/`0x0800`)와 엔트리 순서를 갖는다.
일반 ZIP 라이브러리로 다시 포장하면 꼬리표가 사라지고 헤더 값이 정규화되어 **Samsung Notes가
파일을 열지 못한다.** 그래서 아카이브를 재생성하지 않고, 로컬 헤더·중앙 디렉터리·EOCD를 원본
바이트째 복사하면서 교체 대상 두 엔트리의 CRC·크기와 오프셋만 고쳐 쓴다. 손대지 않은 엔트리는
압축 해제 없이 압축된 바이트 그대로 옮겨진다.

형식 확인과 독립 검증에는 MIT 라이선스 공개 역공학 프로젝트 Dietrich의 문서·파서를 사용한다.
제품 코드에는 Dietrich 전체를 포함하지 않고 필요한 mediaInfo 파서와 안전한 ZIP 교체만 자체 구현한다.
