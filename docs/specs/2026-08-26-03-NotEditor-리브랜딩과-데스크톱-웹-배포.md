# NotEditor 리브랜딩과 데스크톱·웹 배포

**날짜:** 2026-08-26
**상태:** 진행 중

## 왜 하는가
현재 제품명과 저장소·Python 패키지 이름이 PDF 문서 합치기 한 기능만 표현하고, 문서 합치기와
Samsung Notes 필기 이전의 UI 위계도 서로 다르다. Windows 전용 네이티브 파일 대화상자에
의존해 다른 사람이 설치하거나 웹에서 사용하기 어렵고, 설치 과정도 두 스크립트로 나뉘어 있다.

## 목표
제품 전체를 `NotEditor`로 리브랜딩하고, 문서 합치기와 필기 옮기기를 동급 탭으로 제공한다.
같은 핵심 처리 코드를 Windows 데스크톱 앱과 Docker 기반 웹앱에서 사용하며, GitHub Releases의
Windows 설치 파일과 PowerShell 원터치 설치를 모두 제공할 수 있는 배포 구조를 만든다.

## 성공 기준
- [ ] 저장소 폴더가 `C:\dev\NotEditor`, Python 패키지가 `noteditor`가 된다.
- [ ] 앱 제목·로그 경로·바로가기·문서·설치 산출물에서 제품명이 `NotEditor`로 통일된다.
- [ ] 문서 합치기와 필기 옮기기가 같은 위계의 탭으로 전환된다.
- [ ] 문서 합치기의 세 패널 제목부/내용부 경계 높이가 일치한다.
- [ ] 데스크톱과 웹에서 PDF/SDOCX 업로드 및 처리 중 로딩 표시가 보인다.
- [ ] 웹에서 업로드, 미리보기, 문서 합치기 저장, 필기 이전 저장을 실제로 수행할 수 있다.
- [ ] Docker 이미지로 웹앱을 실행할 수 있고 임시 업로드는 세션별로 격리·정리된다.
- [ ] PowerShell 한 번 실행 설치와 GitHub Releases용 Windows 설치 파일 빌드가 모두 마련된다.
- [ ] README에 구조, 설치, 웹 실행, 배포, 테스트 방법이 최신 상태로 기록된다.
- [ ] 전체 자동 테스트가 통과한다.
- [ ] 비공개 `kynbeen/NotEditor` GitHub 저장소에 코드와 핸드오프가 푸시된다.

## 범위 밖
- 특정 클라우드 서비스의 계정 생성, 결제 수단 연결, 운영 도메인·TLS 설정.
- Samsung Notes 자체를 웹에서 실행하거나 SDOCX 형식 전체를 편집하는 기능.
- Windows 이외 운영체제용 네이티브 설치 패키지.

## 제약
- PDF 최종 출력은 기존처럼 원본 PDF 객체를 복사해 품질 손실을 피한다.
- 필기 이전은 원본 SDOCX 획 데이터를 재직렬화하지 않고 보존한다. 미리보기 디코딩은 읽기 전용이다.
- 웹 업로드는 사용자 세션별 임시 디렉터리에 두고, 만료 또는 명시적 초기화 시 삭제한다.
- 데스크톱 앱 기능을 제거하지 않는다. 사용자가 데스크톱과 웹 동시 지원을 선택했다.
- Python 소스는 루트에 평탄화하지 않고 `noteditor` 패키지 아래 둔다. import 경계와 정적 자원
  패키징을 명확히 유지하기 위해서다.

## 고려했다가 안 한 것
| 대안 | 왜 안 했나 |
|---|---|
| Python 파일을 저장소 루트에 모두 평탄화 | 테스트·문서·배포 파일과 런타임 코드가 섞이고 패키지 자원 경계가 사라진다. |
| 웹앱만 남기고 데스크톱 앱 제거 | 사용자가 두 실행 형태를 모두 유지하기로 선택했다. |
| GitHub Pages에 처리 앱 배포 | PyMuPDF와 SDOCX 처리는 Python 서버가 필요해 정적 호스팅만으로 동작하지 않는다. |
| 특정 클라우드에 즉시 배포 | 사용자가 업체 중립적인 Docker 배포 준비를 선택했다. |
