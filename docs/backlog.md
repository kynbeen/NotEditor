# 백로그

현재 상태: `docs/current-status.md`

완료된 작업과 남은 실기 검증을 함께 보존한다. 날짜가 붙은 명세와 인계는 당시 결정의 근거이고,
이 파일의 미완료 체크박스가 현재 작업 대기열이다.

## 모듈: 안정화와 시각적 쪽 정렬 (stability-alignment)

- [x] 새 PDF에 매칭되지 않은 기존 PDF 필기 쪽을 결과 미리보기에서도 실제 배경·필기와 함께
  표시한다. SDOCX·Notewise·Goodnotes의 자동 추정 순서와 저장본의 배경·필기 보존을 검증한다.
- [x] SDOCX의 PDF와 별도로 추가한 노트 쪽은 결과 끝에 몰지 않고 가장 가까운 보존 원본 쪽에
  이어 배치한다. 앞쪽 원본이 삭제된 경우의 위치와 원본 페이지 바이트 보존을 검증한다.
- [x] SDOCX의 PDF와 별도로 추가한 노트 쪽도 검토 목록·결과 쪽 수에 포함한다. 단색 배경·필기
  미리보기, 원본 순서 기반 배치, 웹·데스크톱·Android 공통 API와 저장본 바이트 보존을 검증한다.
- [ ] 별도 노트 쪽의 템플릿·이미지 배경을 실제 샘플로 확인하고 미리보기 지원을 확대한다.
  현재 미지원 배경은 제한을 표시하며, 저장 시 원본 페이지와 리소스는 그대로 보존한다.
- [x] SDOCX의 미매칭 빈 PDF 쪽을 분석 메타데이터로 자동 제외·확인 완료 처리하고 검토 행에서는
  숨긴다. 결과 쪽 수와 저장본을 일치시키며 사용자 제외와 구분해 `빈 원본 자동 생략`으로 알린다.

- [x] 합성 PDF 3개×100쪽과 느린 이미지 렌더를 사용해 미리보기 동시성, 중복 렌더, 캐시 상한,
  헬스체크 응답성을 검증하는 기준 테스트를 추가한다.
- [x] `ComposerSession`의 미리보기 캐시를 크기 제한 LRU와 진행 중 요청 공유 구조로 바꾸고,
  웹 서버에 전역 이미지 렌더 동시성 상한을 추가해 부하 중에도 `/api/health`가 1초 안에 응답하게 한다.
- [x] 브라우저 미리보기를 화면 근처 우선의 제한된 요청 큐로 바꾸고, 같은 이미지 요청을 합치며,
  일시적 GET 실패만 제한적으로 재시도하고 페이지 안에서 다시 시도할 수 있게 한다.
- [x] 필기 파일 업로드를 최소 검증과 분석 작업으로 분리하고 `업로드 → 구조 확인 → 페이지 비교·자동
  매칭 → 필기 좌표 정렬 → 미리보기 준비` 상태를 제공한다. 실패 시 직전 정상 선택을 유지하고
  재업로드 없이 재분석할 수 있는 HTTP·데스크톱 계약과 테스트를 추가한다.
- [x] 문서 합치기와 필기 옮기기에 편집 가능한 결과 파일명 입력을 추가하고 올바른 확장자를 강제한다.
  `문서 비우기`와 `선택 초기화`를 같은 시각적 버튼 체계로 통일하면서 도구별 삭제 경계를 지킨다.
- [x] 자동 `MatchResult`를 사용자 편집 가능한 행 기반 계획으로 변환하는 공통 모델을 추가한다. 모든
  원본·대상 쪽의 단일 포함, 빈 행 금지, 드래그 영향 계산, 확인 상태, 수동 대상 순서 변경을 서버에서
  검증하고 합성 테스트로 고정한다.
- [x] 기존 쪽 매칭 표와 한 장 정렬 미리보기를 약 3쪽 높이의 연속 좌우 비교 화면으로 교체한다.
  지연 로딩, 필기 보기 토글, 불확실·한쪽 전용·수동 변경 강조, 행별 확인, 드래그 전 영향 경고,
  미확인 저장 경고를 구현한다.
- [x] 터치·키보드용 대상 쪽 위·아래 이동 버튼을 추가한다. 제외한 원본·대상 쌍은 이동에
  참여하지 않으며, 확인 취소·경계 이동·변경 중 계획 교체를 실제 JavaScript 실행 테스트로 검증한다.
- [x] 모바일·데스크톱 크기의 Edge에서 새 이동 버튼의 배치와 확인 대화상자 왕복을 검증한다.
  2026-09-06 Playwright 1440×1000·390×844에서 실제 파일 선택, 이동 취소·수락, 확인 상태 초기화,
  빈 원본 자동 생략을 확인했다. 모바일에서 회전 화살표가 파일 선택 버튼을 덮던 오류도 수정했다.
- [x] 행 기반 결과 순서와 대응을 Samsung Notes와 Notewise 저장 경로에 적용한다. 대상 재정렬,
  새 파일 전용 쪽, 필기가 있는 옛 파일 전용 쪽을 보존하고 안전하게 지원할 수 없는 형식·계획은
  저장 전에 명시적으로 거부한다.
- [x] 단위·HTTP·정적 UI·브라우저 상호작용·구조 보존 검사를 모두 실행하고, 명세 성공 기준별 증거를
  점검해 완료된 체크박스와 상태를 갱신한다.

## 모듈: Goodnotes 6 필기 옮기기 (goodnotes-transfer)

조사 모듈이 요구한 실제 샘플이 확보되어 구현으로 넘어갔다. 판정 갱신은
`docs/research/2026-08-30-goodnotes-flexcil-support.md` 의 «Goodnotes 구현 결과» 를 본다.

- [x] `.goodnotes` 의 ZIP·protobuf 바이트 계층과 Apple 프레임 LZ4 해제를 새 의존성 없이 구현한다.
      Notewise와 겹치는 스키마 없는 protobuf 훑기는 `protobuf_wire` 로 합친다.
- [x] `index.events.pb` 의 용지·쪽 생성·쪽 연결 기록에서 쪽 순서, 배경 첨부와 쪽 번호, 캔버스
      크기를 읽고, 쪽 개체 = 내용 − 1 인접 규칙을 지킨다.
- [x] 획의 `tpl` 서명을 해석해 펜·볼펜·연필·형광펜·마커를 미리보기로 그린다. 모르는 객체는
      그리지 않고 건너뛴다(저장 결과에는 남는다).
- [x] 배경 첨부와 그것을 가리키는 사건 기록만 다시 쓰고 `notes/` 필기 저널은 바이트 그대로
      옮긴다. 저장 뒤 다시 읽어 쪽 수·순서·배경 참조를 검증한다.
- [x] 데스크톱·웹 UI의 형식 목록과 저장 확장자에 `.goodnotes` 를 넣고, 실제 파일로 업로드 →
      분석 → 미리보기 → 저장 왕복을 검사한다.
- [ ] **저장 결과를 Goodnotes 앱에서 열어 필기 편집·쪽 재정렬이 되는지 확인한다.** 개발
      환경에 macOS·iPad가 없어 사용자 확인이 필요하다. 이 항목이 닫히기 전에는 README가
      실험 기능으로 안내한다.
- [ ] 여러 쪽 문서와 PDF를 가져와 만든 문서, 스키마 24 파일의 실제 샘플로 같은 왕복을 확인한다.
