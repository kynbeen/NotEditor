# 새 기기 설치와 전체 점검

**날짜:** 2026-08-27
**기기:** LAPTOP
**관련 명세:** `docs/specs/2026-08-26-03-NotEditor-리브랜딩과-데스크톱-웹-배포.md`,
`docs/specs/2026-08-26-02-쪽-매칭과-새-PDF-기준-재조립.md`

## 현재 상태
이 기기에 NotEditor를 처음부터 설치해 실제로 실행되는 것까지 확인했다. 전용 파이썬 환경(venv),
의존성 31개, 아이콘, 시작 메뉴·바탕화면 바로가기가 모두 생겼고 앱이 창을 띄운 채 정상 유지된다.
자동 테스트 89개가 Python 3.14.7에서 전부 통과한다. 웹앱은 실제 HTTP 서버로 띄워 업로드 →
미리보기 → 범위 파싱 → 합치기 내려받기까지 종단 확인했고 결과 PDF의 쪽 순서와 내용이 지정한
대로 나왔다. 설치 중 발견한 실제 버그 하나(`install.ps1`이 Windows 기본 PowerShell에서 파싱
에러로 죽음)를 고쳐 커밋·푸시했다. 명세 03의 성공 기준을 실측 기준으로 갱신했고, 미검증으로
남은 것은 **Docker 이미지 실행**, **설치 파일(.exe) 빌드**, 그리고 명세 02의 **태블릿 Samsung
Notes에서 결과 파일 열기** 세 가지다. 여기에 더해 **GitHub Actions가 최신 푸시에 대해 돌지
않는 문제**를 새로 발견했다.

## 이번 세션에 한 일

- `install.ps1`로 이 기기에 설치했다. venv 생성, 의존성 31개 설치, 아이콘 생성, 시작 메뉴·
  바탕화면 바로가기 등록까지 한 번에 끝났다.
- 설치가 처음에 **실패**했다. `install.ps1`·`setup.ps1`·`install-app.ps1` 세 파일에 UTF-8 BOM
  (파일 첫머리에 붙는 3바이트 인코딩 표식)이 없어서, Windows 기본 PowerShell 5.1이 파일을
  옛 한국어 코드페이지로 읽고 한글이 깨져 문법이 무너졌다. BOM을 붙이고 **PowerShell 5.1에서
  다시 돌려 설치 성공을 확인**했다(`8ceb3ee`).
- 앱을 실제로 띄워 10초간 정상 유지되는 것과 로그 기록(`%LOCALAPPDATA%\NotEditor\app.log`)을 확인했다.
- 전체 테스트 89개를 돌려 통과를 확인했다(Python 3.14.7, Windows 11). 프런트엔드 `app.js`
  구문 검사도 통과했다.
- 웹앱을 `127.0.0.1:8765`에 실제로 띄우고 브라우저처럼 HTTP로 붙어 종단 검증했다. PDF 두 개
  업로드(4쪽·3쪽) → 쪽 미리보기 PNG 수신 → `1-2, 4` 범위 파싱 → 세 쪽을 골라 순서를 섞어
  합치기 → 내려받은 PDF를 열어 쪽 순서와 텍스트가 지정한 대로인지 대조했다.
- 웹 서버 종료 후 임시 세션 폴더가 남지 않는 것을 확인했다.
- 명세 03의 성공 기준 11개를 하나씩 실제로 검증해 체크 상태와 근거를 채웠다. 제품명 통일,
  동급 탭 구조, 패널 헤더 73px, 로딩 표시를 코드에서 직접 확인했다.
- `test` 워크플로에 `docker build` 잡을 추가했다(`caa76dd`). 이 기기에 Docker가 없어 직접
  확인할 수 없는 경로를 CI가 대신 확인하게 하려는 것이다.
- 코드 전체를 훑어 남은 TODO/FIXME가 하나도 없음을 확인했다.

## 내린 결정과 근거

- **BOM 추가로 고쳤다(스크립트를 영어로 바꾸거나 실행 방법을 바꾸지 않았다).** README가 안내하는
  실행 명령 그대로 동작해야 하고, 다른 사람에게 소스를 전달할 때 100% 재현되는 문제였다.
  BOM은 PowerShell 5.1과 7 양쪽에서 UTF-8로 읽히게 하는 가장 작은 수정이다.
- **Docker 검증을 CI로 넘겼다.** 이 기기에 Docker를 새로 설치하는 것은 점검 범위를 넘고,
  `docker build` 잡이 있으면 앞으로 모든 푸시에서 자동으로 확인된다.
- **명세 03의 상태를 "완료"가 아니라 "구현 완료 — 배포 경로 두 개 미검증"으로 적었다.**
  미검증인 것을 완료로 적으면 다음 세션이 확인된 사실로 오해한다.
- **실행 중인 NotEditor 인스턴스 하나를 그대로 두었다.** 01:36:53에 시작된 프로세스가 있는데
  내가 띄운 것이 아니다(내 스모크 테스트 프로세스는 종료를 확인했다). 사용자가 직접 실행했을
  가능성이 높아 임의로 종료하지 않았다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| `PdfComposerError`·`ComposerSession` 등 내부 식별자까지 NotEditor로 개명 | 사용자에게 보이지 않는 이름이고, 전 파일을 건드리는 변경이라 점검 범위를 넘는다. 명세의 성공 기준도 "앱 제목·로그 경로·바로가기·문서·설치 산출물"만 요구한다. |
| `noteditor/web.py`의 사용 중단 예고된 `@app.on_event("shutdown")`을 지금 고치기 | 지금은 경고만 나고 동작한다. 점검이 아니라 코드 변경이라 다음 단계로 넘겼다. |
| 이 기기에 Docker Desktop 설치 | 점검을 위해 큰 도구를 새로 까는 것은 과하다. CI 잡으로 대신한다. |
| 임시 태그(`v0.4.0`)를 붙여 릴리스 워크플로를 시험 실행 | 태그와 GitHub Release는 되돌리기 번거로운 외부 공개 동작이라 사용자 확인 없이 하지 않는다. |

## 미해결 질문 / 블로커

- **GitHub Actions가 최신 푸시에 대해 실행되지 않는다.** 원격 `main`은 `caa76dd`를 가리키고
  워크플로 두 개 모두 `active`, Actions 권한도 `enabled`인데 run이 생성되지 않았다. 전날
  두 번(`a0f7e7e` 실패, `76bb08d` 성공)은 정상 실행됐다. 비공개 저장소의 무료 사용량 소진이
  가장 유력하지만 확인하지 못했다 — `gh`에 `user` 스코프가 없어 billing API를 못 읽는다.
  **이 문제 때문에 방금 추가한 `docker build` 잡도 아직 한 번도 돌지 않았다.**
- **재조립 경로로 만든 SDOCX를 태블릿 Samsung Notes에서 열어본 적이 없다**(명세 02).
  PC에서는 ZIP 구조·꼬리표·해시·보존 바이트까지만 검증 가능하다. 프로젝트 전체에서 가장 큰
  미검증 위험이다.
- 명세 02의 열린 질문들이 그대로 남아 있다: 매칭 '확신 없음' 기준값, `note.note`의
  last edited page index 클램프 필요 여부, 매칭 실패 시 거부할지 사람에게 넘길지.
- 설치 파일(`.exe`) 빌드를 이 기기에서 확인할 수 없다. Inno Setup이 없다.

## 다음 단계

1. GitHub에서 Actions 사용량·결제 상태를 확인한다(Settings → Billing). 무료 분이 소진됐다면
   결제 한도를 올리거나, `test.yml`의 `test` 잡을 `windows-latest`(분당 2배 과금)에서
   `ubuntu-latest`로 옮기는 것을 검토한다. 데스크톱 전용 코드가 아닌 부분은 리눅스에서도 돈다.
2. 태블릿에 결과 `.sdocx`를 옮겨 Samsung Notes에서 열리는지 확인한다. 명세 02의 마지막
   성공 기준이자 프로젝트 최대 위험이다. 확인되면 명세 02의 해당 체크박스를 채운다.
3. `noteditor/web.py:116`의 `@app.on_event("shutdown")`을 FastAPI `lifespan` 방식으로 바꾼다.
   지금은 서버 시작마다 사용 중단 경고가 찍히고, FastAPI 1.0에서 제거될 수 있다.
   `tests/test_web.py`가 이 경로를 이미 덮고 있어 회귀는 테스트로 잡힌다.
4. Docker가 있는 환경에서 `docker compose up --build` 후 `http://localhost:8000`을 실제로
   열어 본다. 또는 1번이 풀려 CI의 `docker` 잡이 도는 것으로 대신한다.
5. 배포할 준비가 되면 `v0.4.0` 태그를 붙여 `windows-release` 워크플로로 설치 파일을 만들고,
   나온 `.exe`를 실제로 실행해 확인한다.
