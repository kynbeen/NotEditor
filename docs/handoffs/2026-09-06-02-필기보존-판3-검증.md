## 현재 상태

새 PDF와 대응하지 않는 기존 필기 쪽은 세 지원 형식에서 추정 순서에 끼워 미리보기와 저장본에
보존한다. SDOCX의 PDF 외 별도 노트 쪽도 원본 순서대로 보존한다. 필기 객체가 없는 미매칭
SDOCX PDF 쪽은 저장기가 원래 생략하던 동작과 맞춰 검토 화면에서도 자동 생략한다.

summary.ai와 NotEditor의 판 3 결정·범위 힌트·사이드카는 양쪽 구현과 테스트가 맞는다.
summary.ai 인계는 재현 가능한 문서별 오름차순 범위를 유지하고 순서 드래그를 숨기며, 일반
NotEditor 합치기는 자유 순서를 유지한다.

## 이번 체크포인트에서 닫은 것

- 족첵 범위 제안의 소유자 경쟁, 앞·뒤 경계, 긴 미확정 꼬리와 힌트 누락을 전용 테스트로 고정했다.
- 실제 handoff JSON을 읽은 뒤 `ComposerApi.suggest_ranges()`까지 가는 통합 경로를 검사했다.
- SDOCX 미매칭 빈 PDF 쪽을 자동 제외·확인 완료 처리하고 검토 행과 결과 쪽 수에서 구분했다.
- summary.ai 인계에서는 결과 순서 재정렬 핸들과 초기화 버튼을 노출하지 않도록 했다.
- 판 3의 `both`를 "처음부터 전부"라고 설명하던 버튼 툴팁을 실제 부분 재실행 의미로 고쳤다.
- README와 상태·명세 문서를 현재 판 번호와 순서 정책에 맞췄다.
- NotEditor에서 판 3 결정과 사이드카를 쓰고 summary.ai에서 읽는 교차 왕복을 확인했다.

## 검증 결과

- NotEditor Python 전체 테스트: 317개 통과
- JavaScript 구문 검사와 `git diff --check`: 통과
- Android `testDebugUnitTest assembleDebug`: 성공
- summary.ai 전체 테스트: 323개 및 하위 테스트 11개 통과
- 합성 브라우저 검증: 별도 노트와 미매칭 필기 쪽의 원본 순서·배경·필기 렌더 확인

빈 원본 자동 생략과 summary.ai 순서 잠금은 브라우저 연결이 끊긴 뒤 추가되어 Node·정적 테스트와
Android 빌드로 확인했다. 이 두 항목의 최신 화면 실측은 아직 하지 않았다.

## 결정과 근거

- 필기가 있는 미매칭 기존 쪽은 사용자 작업물이므로 새 PDF에 없다는 이유로 버리지 않는다.
- 필기 없는 미매칭 SDOCX PDF 쪽은 저장 결과에 존재하지 않으므로 검토 화면에서도 조용히 세지
  않고, 자동 생략 사실만 요약에 남긴다.
- summary.ai 범위 인계에 자유 순서를 열려면 판 4와 양쪽 재현기를 늘려야 한다. 범위 선택 중심
  흐름에서 얻는 이익보다 유지보수 비용과 표현 불일치 위험이 커서 현재 계약을 유지한다.
- 판 3 `both`는 본문 영향 단계 재실행과 변경 문제 쪽 부분 재추출의 조합이다. 판 2 호환용 내부
  값 `all`과 같은 전면 재실행으로 설명하거나 처리하지 않는다.
