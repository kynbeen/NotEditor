# 굿노트 6 대응과 첫 릴리스 인계

**날짜:** 2026-09-01
**기기:** LAPTOP
**관련 문서:** `docs/research/2026-08-30-goodnotes-flexcil-support.md`, `docs/backlog.md`

## 현재 상태

NotEditor는 Samsung Notes·Notewise에 더해 **Goodnotes 6 `.goodnotes` 필기 옮기기**를
지원한다. 데스크톱·로컬 웹 양쪽에서 업로드 → 분석 → 쪽 대조 미리보기 → 저장 흐름을 그대로
타며, 결과는 원본과 같은 `.goodnotes` 형식으로 나온다. UI와 README는 이 형식을 **실험 기능**
으로 명시한다.

저장소는 공개 상태이고 **`v1.0.0` 이 첫 정식 릴리스**다. 초보자가 릴리스 페이지에서 설치
파일을 받아 실사용까지 가는 안내 문서와, 그 과정을 명령 한 줄로 끝내는 스크립트를 두었다.

- 릴리스: <https://github.com/kynbeen/NotEditor/releases/tag/v1.0.0>
- 산출물: `NotEditor-Setup-1.0.0.exe` (43.5 MB, 초안 아님·정식)
- 릴리스 워크플로(빌드 33407445547)는 검사 229개 통과 후 PyInstaller·Inno Setup을 거쳐 성공했다.

## 이번 세션에 한 일

- `.goodnotes` 의 ZIP·protobuf 바이트 계층과 Apple 프레임 LZ4 해제를 **새 의존성 없이** 구현했다.
- `index.events.pb` 의 용지·쪽 생성·쪽 연결 기록에서 쪽 순서, 배경 첨부와 그 안의 쪽 번호,
  캔버스 크기를 읽는 쪽 모델을 만들었다.
- 획의 `tpl` 서명을 해석해 펜·볼펜·연필·형광펜·마커를 미리보기로 그린다.
- 배경 첨부와 그것을 가리키는 사건 기록만 다시 쓰고 `notes/` 필기 저널은 바이트 그대로 옮기는
  저장 경로를 만들었다. 저장 뒤 다시 읽어 쪽 수·순서·배경 참조를 검증한다.
- Notewise와 겹치던 스키마 없는 protobuf 훑기를 `protobuf_wire.py` 로 합쳤다.
- 데스크톱·웹 UI의 형식 목록·저장 확장자·안내 문구에 `.goodnotes` 와 **"Goodnotes 6"** 를 넣었다.
- 실제 Goodnotes 6 Mac 내보내기 파일을 `tests/fixtures/goodnotes/` 에 두고 그것을 기준으로 하는
  검사 26개를 추가했다. 전체 229개 통과.
- 초보자용 [설치와 첫 사용 안내](../설치와-첫-사용.md)와 원터치 설치 스크립트
  `install-online.ps1` 을 추가하고 README에서 연결했다.
- README의 "저장소가 비공개라 설치 파일을 별도 전달" 이라는 낡은 안내를 걷어냈다.
- `v1.0.0` 태그를 밀어 Windows 설치 파일 릴리스를 만들었다.

## 내린 결정과 근거

- **필기 저널은 바이트 하나 건드리지 않는다.** 획을 다시 인코딩하면 앱에서 뭉개진 자국으로
  열리는 것이 알려져 있다. 그래서 배경 첨부와 참조만 다시 쓰고, 이 경계를 넘지 않는 것을
  이 형식 지원의 핵심 계약으로 삼았다.
- **쪽 개체 ID = 쪽 내용 ID − 1** 인접 규칙을 지킨다. 실제 파일에서 성립하고, 아무 UUID나 쓰면
  앱이 문서는 열되 그 쪽을 빈 쪽으로 보여준다.
- **결과에 새 문서 ID를 부여한다.** 원본과 같은 ID면 두 파일을 다 가져왔을 때 앱이 같은 문서로
  보고 원본을 덮을 수 있다.
- **사라진 쪽을 가리키는 보기 상태 기록은 옮기지 않는다.** 없어도 문서는 열리고, 남기면 없는
  쪽을 가리킨다.
- **앱 왕복 검증 전이지만 UI에 노출한다(사용자 결정).** 대신 파일을 고르기 전에 보이는 자리에
  실험 경고를 두고, README·안내 문서가 "원본을 따로 보관하라"고 먼저 말한다.
- **첫 릴리스를 `v1.0.0` 으로 붙였다(사용자 결정).** 합치기·Samsung Notes·Notewise는 이미
  실사용 중이고 설치 패키지도 갖춰져 있어 초기 단계 번호가 실제와 맞지 않는다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 획을 우리 인코더로 다시 써서 저장 | 앱이 뭉개진 자국으로 렌더한다고 알려져 있다. 원본 저널 복사가 유일하게 검증된 경로다. |
| `lz4` 패키지를 의존성에 추가 | 블록 형식이 단순하고 **읽기만** 하면 된다. 배포 크기와 공급망을 늘릴 이유가 없었다. |
| 도형·이미지·글상자도 미리보기에 그리기 | 형식이 확정되지 않았다. 안 그릴 뿐 저장 결과에는 그대로 남으므로 손해가 없다. |
| `notewise_proto.py` 를 그대로 두고 파서를 또 복제 | 세 번째 복제가 된다. 오류 타입만 형식별로 두고 훑기는 `protobuf_wire` 로 합쳤다. |
| `irm … \| iex` 한 줄 설치 | PowerShell 5.1이 BOM 없는 응답의 한글을 깨뜨린다. 파일로 내려받아 실행하는 형태로 바꿨다. |
| 릴리스를 `gh release create` 로 직접 생성 | 태그를 밀면 워크플로가 빌드·검사까지 하고 릴리스를 만든다. 손으로 만들면 그 검사를 건너뛴다. |

## 미해결 질문 / 블로커

**저장한 `.goodnotes` 를 Goodnotes 앱에서 열어 본 적이 없다.** 이 개발 환경에 macOS·iPad가
없어서 직접 확인할 수 없다. 이것이 유일한 실질 블로커이고, 사용자만 닫을 수 있다.

그 밖에 확인 못 한 범위:

- 검증에 쓴 실제 파일은 **한 쪽짜리, 기본 용지(가져온 PDF 아님) 문서 하나**뿐이다. 여러 쪽
  문서와 PDF를 가져와 만든 문서는 같은 코드 경로를 타지만 실제 파일로 확인하지 못했다.
- 스키마 24(iPad 시절) 파일로 확인하지 못했다.
- Apple과 Android·Windows의 `.goodnotes` 가 같은 구조라는 증거는 없다.
- 도형·이미지·글상자는 미리보기에 그리지 않는다(저장 결과에는 남는다).

원터치 설치 스크립트는 **최신 릴리스 조회 → 자산 선택 → 내려받기 → 크기 대조 → MZ 헤더
확인**까지 실제 릴리스로 확인했다. 마지막 `Start-Process`(설치 실행)만 이 PC 상태를 바꾸므로
돌리지 않았다. 다른 PC에서 한 번 끝까지 돌려 보는 것이 남았다.

## 다음 단계

1. **Goodnotes 6에서 노트를 `.goodnotes` 로 내보내 한 번 돌려 보고, 결과를 앱으로 다시
   가져와 필기 편집·쪽 재정렬이 되는지 확인한다.** 되면 `docs/backlog.md` 의
   `goodnotes-transfer` 모듈에서 해당 항목을 닫고, README·UI의 실험 경고를 걷어낸다.
2. 여러 쪽 문서와 PDF를 가져와 만든 문서로 같은 왕복을 확인한다. 여기서 깨지면 볼 곳은
   `goodnotes_archive.background_pdf` 와 `build_events` 의 용지 기록 부분이다.
3. 릴리스 설치 파일을 **다른 PC에서 실제로 받아 설치**해 SmartScreen 안내가 문서대로인지,
   원터치 명령이 끝까지 도는지 확인한다.
4. Flexcil은 아직 «추가 샘플 필요» 상태다. 같은 방식(실제 파일 확보 → 오라클 대조 → 구현)이
   가능한지 조사 문서의 Flexcil 절을 다시 본다.
