# Goodnotes 목차 제거와 정렬 확인 정책

**날짜:** 2026-09-07
**기기:** LAPTOP
**관련 명세:** `docs/specs/2026-08-30-01-NotEditor-안정화와-시각적-쪽-정렬.md`

## 현재 상태

질문 문서에 기록된 사용자 답변을 반영했다. Goodnotes 목차 기능은 제거했으며 구현 대기에서
제외했다. 낮은 정렬 품질은 모든 대응 쪽을 확인 필요로 표시하고 사용자가 명시 확인한 후 저장한다.
미매칭 필기 보존과 판 3 인계 기능은 유지된다. 실제 앱·기기 검증은 계속 남아 있다.

## 이번 세션에 한 일

- Goodnotes 목차 JSON 입력·생성, API 인자, Android 파일 선택기·브리지와 전용 테스트를 제거했다.
- 기존 목차가 있는 원본의 저장 중단 검사는 유지하고 원본·기존 출력 보존 검사를 추가했다.
- HTTP 저장 요청은 제거된 목차 옵션 등 정의되지 않은 필드를 거절한다.
- `Alignment.requires_confirmation`에 가로·세로 배율 불일치, 잔차 50mm 초과, 경계 이탈 추정
  5mm 이상의 공통 정책을 추가했다. 판정은 반올림 전 포인트 값으로 한다.
- 공통 분석 응답에서 저품질 정렬의 자동 매칭 쪽도 확인 필요로 바꾼다. 원본 매칭 점수는 보존한다.
- 대응 계획을 생략하거나 구형 숫자 매핑으로 보내는 저장도 저품질 정렬에서는 명시 승인을 요구한다.
- 경고를 주황색 확인 필요로 표시하고, 재조립 모드에도 정렬 경고를 표시한다.
- README·백로그·상태·명세와 질문 반영 기록을 정리했다.

## 내린 결정과 근거

- 사용자가 목차 기능을 당분간 구현하지 않기로 했으므로 입력 UI만 숨기지 않고 실행 경로를 제거했다.
- 기존 목차 손실 방지 검사는 필기 전송의 데이터 보호이므로 유지한다. 기존 목차 보존 구현은 안 한다.
- 사용자가 권장한 확인 후 저장 정책을 선택했으므로 변환 자체를 다른 방식으로 바꾸거나 저장을
  무조건 거절하지 않는다. 확인되지 않은 상태만 차단한다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| Goodnotes 기존 목차 추가·교체 구현 | 사용자 요청으로 목차 기능 전체를 당분간 접었다. 명세에 반영했다. |
| 낮은 품질이면 저장 거절 또는 자동 가운데 맞춤 | 사용자가 명시 확인 후 저장하는 정책을 선택했다. |

## 검증 결과

- Python 전체 303개 통과. 삭제 기능 전용 테스트를 제거했기 때문에 이전 317개보다 줄었다.
- JavaScript 구문 검사, diff 공백 검사 통과.
- Android `testDebugUnitTest assembleDebug` 성공. 처음 발견한 제거된 콜백의 종료 처리 참조도 제거했다.
- 이전 실물 대조 자료 재분석: Goodnotes 잔차 60.96mm·축 불일치는 확인 필요, SDOCX·Notewise
  잔차 30.2mm·축 일치는 품질 확인 기준에 걸리지 않는다.
- Edge 1440×1000·390×844에서 실제 파일 선택, 목차 UI 부재, 저품질 대응 미확인 상태,
  계획 없는 HTTP 저장 차단, 확인창 취소, 명시 승인 다운로드와 다운로드 쪽 수를 검증했다.
- 같은 실행에서 SDOCX 미매칭 빈 원본 생략·별도 노트 보존과 이동 취소·수락도 다시 확인했다.
- 로컬 캡처·다운로드: `tmp/browser-review-2026-09-06/`; 스크립트 `tmp/review_browser_qa.py`.
  이 파일들은 git 제외이며 검증용 서버·브라우저는 실행 후 종료했다.
