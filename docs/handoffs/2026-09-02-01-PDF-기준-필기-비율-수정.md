# PDF 기준 필기 페이지 비율 수정 인계

**날짜:** 2026-09-02
**기기:** LAPTOP
**관련 명세:** `docs/specs/2026-09-02-01-PDF-기준-필기-페이지-비율.md`

## 현재 상태

SDOCX·Notewise·Goodnotes의 필기 옮기기 결과가 원본 필기 문서가 아니라 **대상 PDF의 페이지
크기와 비율**을 따르도록 구현했다. 기존 본문 정렬은 대상 PDF 좌표에서 필기 캔버스로 역변환해
유지한다. 비율 변경 산출물의 웹 다운로드와 저장 후 구조 검증까지 자동 검사로 통과했지만, 실제
Samsung Notes·Notewise·Goodnotes 앱으로 가져오는 왕복 검증은 아직 하지 못했다. 기능 코드는
`9b1535e`, 명세 시작점은 `5a0ccfb`에 커밋되어 있다.

## 이번 세션에 한 일

- 잘림의 원인을 `place_page`가 새 PDF를 원본 크기 MediaBox에 다시 그리는 구조로 특정했다.
  비율이 다르면 목적 사각형 일부가 원본 페이지 밖으로 나가 실제로 잘렸다.
- 공통 `CanvasTransform`을 만들어 PDF 본문 정렬의 역변환을 각 앱의 필기 좌표에 적용했다.
- 대상 쪽은 대상 PDF 페이지를 원래 크기 그대로 넣고, 대상이 없는 원본 전용 필기 쪽만 옛
  배경과 비율을 유지하도록 행 계획 PDF 생성 규칙을 바꿨다.
- Samsung Notes는 `.page`의 캔버스, PDF 사각형, 배경 너비, 획 경계·점·굵기를 고정 길이에서
  수정한다. 압축 델타 좌표도 다시 인코딩한다.
- Notewise는 페이지 캔버스와 모든 페이지 객체의 2D 변환 행렬을 합성한다. 알 수 없는 객체도
  제거하지 않고 같은 객체 레코드에 변환만 적용한다.
- Goodnotes는 실제 Goodnotes 6 fixture의 세 TPL 획 서명을 대상으로 점·굵기를 변환하고,
  Apple LZ4 무압축 프레임으로 다시 싼다. 획 레코드 수는 저장 전후에 검증한다.
- 수동 쪽 대응을 고른 경우 그 실제 쪽 짝으로 정렬을 다시 계산하며, 한 쪽 문서도 정렬 표본으로
  사용할 수 있게 했다. 수동 미리보기도 같은 정렬을 사용한다.
- 세 형식 모두 저장 뒤 PDF 페이지 수·비율, 캔버스 비율, 필기 객체/레코드 수와 참조를 다시
  읽어 검증한다.
- 서로 다른 비율의 세 형식 웹 다운로드 회귀 검사를 추가했다. 전체
  `python -m unittest discover -s tests -v` **234개가 통과**했고 `git diff --check`도 통과했다.
- PR 검토를 시작했지만 devkit 설정의 `targets`가 비어 있어 목록 조회 단계에서 중단했다.

## 내린 결정과 근거

- **배경을 원본 캔버스에 맞추지 않고 필기를 대상 캔버스로 옮긴다.** 대상 PDF를 유일한 페이지
  기준으로 삼아야 새 영역을 자르지 않으면서 본문 위치를 유지할 수 있다.
- **좌표 변환은 PDF 정렬의 역변환이다.** 기존 정렬 추정은 대상 PDF를 원본 PDF로 옮기는
  변환이므로, 편집 가능한 필기는 반대로 원본 캔버스에서 대상 캔버스로 이동해야 한다.
- **대상과 같은 순서로만 구성된 결과는 대상 PDF 바이트를 그대로 넣는다.** 불필요한 PDF
  재생성을 피하고 사용자가 선택한 PDF를 보존한다.
- **모르는 편집 데이터를 평탄화하거나 버리지 않는다.** 지원하지 않는 Goodnotes 획 좌표가
  실제 변환 대상이면 조용히 누락하지 않고 저장을 거절한다.
- **Goodnotes 저널 불변 계약은 비율이 같을 때만 유지한다.** 비율이 달라진 상황에서는 편집
  가능한 좌표를 옮기려면 TPL 좌표를 수정해야 한다. 실제 fixture에서 획 종류와 수 보존을
  확인했지만 앱 수용 여부는 별도 실기 검증 대상으로 남겼다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 새 PDF를 원본 페이지 박스 안에 계속 다시 그리기 | 이번 잘림의 직접 원인이며 대상 PDF 비율을 잃는다. |
| PDF를 원본 비율로 늘이거나 찌그러뜨리기 | PDF와 필기 모양을 왜곡한다. |
| 필기를 PNG로 평탄화하기 | 앱에서 편집 가능한 획과 도구 속성을 잃는다. |
| 모르는 Goodnotes 획을 그대로 두고 알려진 획만 옮기기 | 좌표가 섞이고 일부 필기가 잘릴 수 있어 무누락 요구를 어긴다. |
| devkit을 우회해 PR을 직접 머지하기 | 검토 스킬의 대상 설정과 사용자 머지 승인을 건너뛸 수 없어 중단했다. |

## 미해결 질문 / 블로커

- 실제 비율 차이 SDOCX·Notewise 샘플이 저장소와 `C:\dev` 아래에 없다. 현재 SDOCX와
  Notewise 검증은 합성 구조, Goodnotes는 실제 Mac 내보내기 fixture를 사용했다.
- 세 앱에서 결과를 가져와 페이지 전 영역, 필기 위치, 펜·형광펜 편집이 되는지 확인하지 못했다.
  특히 Goodnotes의 무압축 Apple LZ4 프레임 수용과 Samsung Notes의 실제 델타 획 변환은 실기
  확인이 필요하다.
- PR 검토 명령 `python c:/dev/devkit/tools/autodev/review.py list`는
  `targets.TargetError: 설정에 targets 가 비어 있다`로 실패했다. devkit 대상 저장소 설정 없이는
  대기 PR을 식별하거나 안전하게 소화할 수 없다. PR은 하나도 머지하지 않았다.
- 조사용 외부 저장소 사본 `tmp/Dietrich-review/`는 `.gitignore`의 `tmp/` 아래에 있어 Git에는
  잡히지 않는다. 삭제 명령은 실행 정책에 막혔으므로 재개 뒤 필요 없으면 직접 지운다.

## 다음 단계

1. `C:\dev\devkit` 설정에서 NotEditor의 `targets` 항목을 채운 뒤
   `python c:/dev/devkit/tools/autodev/review.py list`를 다시 실행하고, 대기 PR을 현재
   `9b1535e` 기능과 충돌하는지 검토한다. 사용자 승인 전에는 머지하지 않는다.
2. 비율이 다른 실제 SDOCX·Notewise·Goodnotes 입력을 `imports/` 사본으로 넣어 세 앱에 결과를
   가져오고, 페이지 네 변·필기 위치·편집 가능성을 확인한다. Drive 원본은 읽기 전용으로 둔다.
3. 실기 실패 시 `sdocx_ink.transform_page_ink`,
   `notewise_transfer._transform_page_object`, `goodnotes_ink._transform_tpl` 순으로 산출물의 첫
   변환 획을 원본과 대조한다.
4. 실기 성공 시 관련 명세의 남은 두 체크 항목을 닫고 Goodnotes 실험 경고 유지 여부를 결정한다.
