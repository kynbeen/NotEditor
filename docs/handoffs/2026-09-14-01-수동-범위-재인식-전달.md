# 수동 범위 재인식 전달 구현

**날짜:** 2026-09-14
**기기:** LAPTOP
**관련 명세:** `C:/dev/summary.ai/docs/specs/2026-09-14-04-수동-범위-재인식-캐시-갱신.md`

## 현재 상태
강의록을 올린 직후 자동 제안은 기존 캐시 정책을 유지하고, 사람이 `범위 자동 인식`을 누른
호출만 summary.ai에 `refresh: true`를 보낸다. 불확실한 답이 파일을 누락하면 기존 선택을
지우지 않는다. 실행 중인 NotEditor 창은 재시작하지 않아 실창 확인만 남았다.

## 이번 세션에 한 일
- `request_scope`와 `ComposerApi.suggest_scope`에 선택적인 수동 갱신 의도를 연결했다.
- 화면의 `auto` 상태를 API의 `refresh`로 변환했다.
- `uncertain`인 파일 누락 시 기존 쪽 선택을 보존했다.
- 전체 단위 테스트 324개를 통과했다.

## 내린 결정과 근거
`refresh`는 선택 필드로 두고 자동 호출에서는 생략했다. 옛 summary.ai와 요청 모양을 유지하면서
사람이 다시 누른 의도만 새 서버에 전달할 수 있다.

## 고려했다가 안 한 것
| 대안 | 왜 안 했나 |
|---|---|
| 모든 범위 요청에 `refresh` 전송 | 자동 최초 호출의 캐시 이점을 없앤다 |
| 불확실한 누락도 선택 비우기 | 모델의 낮은 확신이 사람의 기존 선택을 파괴한다 |

## 변경한 파일
| 파일 | 무엇을 / 왜 |
|---|---|
| `noteditor/merge_handoff.py` | 선택적인 `refresh` 요청 필드 |
| `noteditor/app.py` | UI 의도를 네트워크 요청으로 전달 |
| `noteditor/static/app.js` | 자동/수동 구분과 불확실 선택 보존 |
| `tests/test_scope_api.py` | 요청·브리지·정적 UI 회귀 검증 |

## 미해결 질문 / 블로커
기능 블로커 없음. 실행 중 창은 옛 코드를 메모리에 올린 상태라 재시작 뒤 실창 확인이 필요하다.
