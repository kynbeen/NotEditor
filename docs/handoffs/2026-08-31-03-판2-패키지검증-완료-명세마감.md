## 현재 상태

지난 세션에 남아 있던 마지막 항목인 최신 패키지 검증을 끝냈다. PyInstaller(파이썬 코드를 단독
실행 파일로 묶는 도구) 빌드를 중단 없이 완주해 `dist\NotEditor\NotEditor.exe`가 최신 커밋
`446617e` 기준(`0.0.0+446617e`)으로 갱신됐다. 체크아웃과 패키지 양쪽에서 판 2 `review` 계획과 빈
`merge` 계획이 실제로 열리는 것을 확인했고, 전체 189개 테스트도 다시 통과했다. 명세는 `완료`로
닫았고(`e0045dd`) 작업 트리는 깨끗하다. summary.ai 쪽 판 2 구현은 이미 끝나 있어 이 작업 단위는
양 저장소 모두 종료 상태다.

## 이번 세션에 한 일

- `venv\Scripts\pyinstaller.exe --noconfirm NotEditor.spec`을 끝까지 실행했다(종료 코드 0).
- 검증용 판 2 계획 JSON 세 개를 실제 수집함 PDF로 만들었다(`tmp/`, 추적 대상 아님).
- 체크아웃에서 숨긴 창으로 실제 프런트엔드를 띄워 `review` 화면의 DOM(화면을 이루는 요소 구조)을
  직접 확인했다 — 비교 행, 두 열 미리보기 칸, 상태 배지, 생성 방식별 갱신 버튼 문구, 기준 문서가
  합치기 문서 목록에서 빠진 것.
- 같은 쪽 판정이 실제로 나오는지 보려고 양성 대조를 따로 만들었다. 41쪽짜리 `-선택` PDF를 기준으로,
  그것이 잘려 나온 87쪽 원본을 대상으로 비교해 **동일 41쪽 · 현재 전용 46쪽 · 사용본 전용 0쪽 ·
  확인 필요 0쌍**을 얻었다.
- `origin: selected`는 `전체 갱신`, `origin: merged`는 `합쳐서 갱신` 버튼이 나오는 것을 각각 확인했다.
- 패키지 실행본을 `--open-plan`으로 두 계획 모두 띄워, 창 제목에 계획 제목이 반영되고 로그에
  오류가 없으며 프로세스가 살아 있는 것을 확인했다.
- 빈 합치기 계획에서는 Win32 창 목록을 열거해 파일 선택 대화상자(`#32770`, 제목 "열기")가
  실제로 뜬 것을 확인했다.
- `venv\Scripts\python.exe -m unittest discover -s tests -q` → 189개 통과.
- 명세의 마지막 체크박스를 채우고 상태를 `완료`로 바꿔 별도 커밋했다.

## 내린 결정과 근거

- 패키지 검증을 "프로세스가 안 죽는다"에서 멈추지 않고 **창 제목과 대화상자 존재**까지 봤다.
  계획 제목은 계획을 실제로 읽었을 때만 창 제목에 붙고, 대화상자는 빈 계획일 때만 자동으로
  뜬다. 둘 다 계획이 적용됐다는 관찰 가능한 증거다.
- 화면 내용 검증은 체크아웃에서 했다. 패키지 실행본은 안에 든 프런트엔드를 밖에서 들여다볼
  수단이 없고, 같은 코드가 들어 있으므로 DOM 확인은 체크아웃에서 한 번 하면 충분하다.
- 양성 대조를 추가한 이유: 처음 쓴 실제 번들 PDF는 대상 파일과 무관한 문서라 "동일 0쪽"이
  나왔다. 그대로 뒀으면 **비교 엔진이 고장 나서 0쪽인 경우와 구분할 수 없다.** 부분집합 관계가
  확실한 두 파일로 다시 재 41쪽 전부가 동일로 잡히는 것을 확인했다.
