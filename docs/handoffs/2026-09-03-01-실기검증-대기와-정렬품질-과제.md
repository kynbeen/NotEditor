**기기:** LAPTOP

## 현재 상태

코드는 다 올라갔다. `main` = `1ff4298`, 작업 트리 깨끗, `origin/main` 과 동일, 전체 자동 검사
**241개 통과**. 이번 세션에 새로 커밋할 코드는 없었다.

기능 쪽은 **사람이 태블릿에서 확인하는 단계 하나만 남았다.** 실기 검증용 결과 파일과 대조
그림이 `tmp/실기검증/` 에 준비되어 있다(git 에는 안 올라간다 — `.gitignore` 의 `tmp/`, 200MB
넘는 개인 강의자료라 의도적이다). 그 확인을 하기 전까지 명세의 성공 기준 두 항목은 열려 있다.

검증 과정에서 **정렬 추정에 품질 기준이 없다는 문제**를 새로 찾았고, 어떻게 대응할지가
설계 판단이라 손대지 않고 명세의 열린 질문으로 올렸다.

## 이번 세션에 한 일

- `main` 을 `origin` 에 푸시해 세 커밋(`757b544`, `4d11f43`, `1ff4298`)을 올렸다. 푸시 상태를
  다시 확인했고 앞서 있던 커밋은 없다.
- 최근 닷새(08-31 ~ 09-02)의 작업을 핸드오프 5건과 커밋 이력에서 정리해 문서로 만들어
  아티팩트로 발행했다: <https://claude.ai/code/artifact/49a5f5ba-08a5-4a1c-96bc-70c78d316e0e>
  (읽기용 요약 문서다. 저장소 파일이 아니라 링크로만 존재한다.)
- 명세 `2026-09-02-01` 을 갱신했다 — 접은 경로 2건 추가, 해소된 열린 질문 표시, 정렬 품질
  문제를 새 열린 질문으로 추가, 변경 이력 한 줄.

## 내린 결정과 근거

- **정렬 추정 품질 문제를 임의로 고치지 않았다.** 잔차가 크면 거절할지·경고하고 진행할지·
  단순 변환으로 되돌릴지는 사용자가 겪는 실패 모양을 바꾸는 설계 결정이다. 잘못 고르면
  "옮기기가 자꾸 거절된다" 또는 "조용히 어긋난 채 저장된다" 중 하나가 된다.
- **작업 요약을 저장소 문서가 아니라 아티팩트로 만들었다.** 읽기용 회고이지 프로젝트가
  참조하는 계약이 아니다. `docs/` 에 넣으면 다음 세션이 읽어야 할 문서만 늘어난다.
- **`tmp/실기검증/` 을 git 에 올리지 않는다.** 실제 강의자료 원본과 결과가 200MB 넘고
  개인 자료다. 필요하면 `tools/make_ratio_check_set.py` 로 언제든 다시 만든다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 정렬 잔차 임계값을 내가 정해서 바로 넣기 | 쓸 만한 값을 모른다. 시각적으로 정확했던 SDOCX 도 잔차 30.2mm 였고, 어긋난 Goodnotes 는 61mm 였다. 근거 없는 숫자는 오작동을 옮길 뿐이다. |
| 작업 요약을 `docs/` 안에 파일로 남기기 | 읽기용 회고라 다음 세션이 읽어야 할 문서만 늘린다. |
| PR #2 를 이번에 리베이스 | 사용자가 보류를 골랐다. 뒤집지 않는다. |
| 검증 세트를 저장소에 커밋 | 200MB 넘는 개인 강의자료다. 도구로 재생성한다. |

## 미해결 질문 / 블로커

- **세 앱 왕복 확인이 안 됐다.** 태블릿과 화면 조작이 필요해 이 환경에서 직접 할 수 없다.
  확인 항목은 `tmp/실기검증/읽어주세요.md` 에 적어 두었다. 이게 명세 성공 기준 두 항목을
  막고 있는 유일한 블로커다.
- **정렬 추정에 절대 품질 기준이 없다.** `noteditor/transfer_plan.py` 의 `alignment_for_pairs`
  는 쪽 크기가 다를 때 추정치를 잔차와 무관하게 그대로 쓴다. `improves`·`axes_agree` 검사는
  크기가 **같을 때만** 걸린다. `병리_이소민 4-2.goodnotes` 에서 배율 0.911·잔차 172.8pt(약
  61mm) 짜리 추정이 그대로 적용돼 필기가 한 줄 위로, 가로로도 어긋났다. 같은 방식으로 만든
  `약리학_1주차(1)...goodnotes` 는 정확했으니 형식 문제가 아니다. 임계값 후보는 미확인.
- **PR #2(Goodnotes 목차)가 열려 있다.** `9b1535e` 이전 코드 기준이라 그대로 머지하면
  비율 수정이 되돌아간다. GitHub 에 코멘트는 남기지 않았다.
- devkit 무인 루프 설정(`tools/autodev/config.json`)은 이 기기에 없다. 포크에서 온 PR 은
  `review.py list` 의 슬러그 매칭으로 잡히지 않으므로, PR 검토는 당분간 직접 한다.

   같은 폴더의 `대조-결과.png` 와 앱 화면이 같으면 옮기기는 정상이다.
2. 실기 성공 시 `docs/specs/2026-09-02-01-...md` 의 성공 기준 마지막 두 항목을 `[x]` 로 닫고,
   Goodnotes 실험 경고(`noteditor/static/index.html` 과 README)를 유지할지 정한다.
3. 정렬 품질 기준을 정해 `noteditor/transfer_plan.py` 의 `alignment_for_pairs` 에 넣는다.
   현재 `if same_geometry and not (alignment.improves and alignment.axes_agree): return None`
   이 크기가 같을 때만 걸리므로, 크기가 다를 때도 잔차 기준으로 걸리게 하고 걸렸을 때의
   동작(거절 / 경고 후 진행 / 항등 변환 대체)을 결정한다. 임계값은 실물 자료 여러 개의
   잔차를 뽑아 정한다 — `tools/make_ratio_check_set.py` 가 저장 보고에 잔차를 찍는다.
4. PR #2 를 `9b1535e` 위로 리베이스한다. 충돌 파일은 `noteditor/goodnotes_transfer.py` 와
   `tests/test_web.py` 이고, 살려야 할 것은 `ink_transform.canvas_transform`,
   `transform_goodnotes_journal`, `alignment_for_plan` import 와 대상 PDF 바이트 보존 경로다.
