# NotEditor 안정화·로컬 웹·summary.ai 합치기 인계 완료

**날짜:** 2026-08-31
**기기:** LAPTOP
**관련 명세:** `docs/specs/2026-08-30-01-NotEditor-안정화와-시각적-쪽-정렬.md`,
`docs/specs/2026-08-30-02-NotEditor-로컬-웹-실행기.md`,

## 현재 상태

사용자가 확정한 NotEditor 안정화·시각적 쪽 정렬, 로컬 웹 실행기, summary.ai 합치기 인계 계약 판 1을
모두 구현하고 검증했다. 코드와 완료 문서는 각각 `4bc0e7a`, `1110cc9` 이후 커밋까지 분리되어 있고,
이 인계 문서를 쓰기 직전 작업 트리는 깨끗하다. `summary.ai`와 `workspace`는 계약과 핸드오프를 읽고
테스트만 실행했으며 두 저장소 모두 수정하지 않았다. NotEditor `main`은 인계 전 기준
`origin/main`보다 14커밋 앞서 있어 이 문서 커밋과 함께 푸시해야 한다.

## 이번 세션에 한 일

- 여러 대용량 PDF 미리보기 요청을 제한하고 중복 렌더 공유, 크기 제한 LRU 캐시, 부하 중 헬스체크
  우선 응답, 페이지 내부 오류·재시도를 구현했다.
- 필기 파일 업로드와 분석 단계를 분리하고 실패 시 선택 유지·재분석, 편집 가능한 결과 이름,
  도구별 통일된 초기화 버튼을 구현했다.
- 한 장씩 멈추던 기존 매칭 화면을 약 3쪽 높이의 연속 좌우 정렬 화면으로 교체했다. 필기 표시 토글,
  불확실·한쪽 전용·수동 행 강조, 행별 확인, 새 PDF 쪽 드래그 순서 변경과 앱 내부 경고를 넣었다.
- Samsung Notes SDOCX와 Notewise 저장 경로가 같은 행 기반 계획을 사용하게 하고, 옛 파일 전용 필기와
  대상 재정렬을 보존하도록 했다. Goodnotes와 Flexcil은 공식 자료를 조사해 실제 원본 샘플 확보 전에는
  지원을 표시하지 않기로 기록했다.
- `NotEditor 로컬 웹` 실행기를 추가했다. `127.0.0.1:8765` 전용 서버를 Edge/Chrome 앱 모드로 열고,
  정상 로컬 인스턴스만 재사용하며 앱 창 종료 시 소유 서버도 종료한다. PyInstaller는 기존
  `NotEditor.exe`와 `NotEditorLocalWeb.exe`를 함께 만든다.
- workspace의 `summary-ai↔noteditor-합치기` 계약 판 1과 summary.ai 최신 핸드오프를 읽어
  `--open-plan`, `ComposerApi.startup_plan()`, 고정 결과 경로 저장과 `.merge.json` 사이드카를 구현했다.
  PDF를 먼저 저장하고 실제 화면 순서를 사이드카로 원자 기록하며, 규격으로 손실 없이 표현할 수 없는
  수동 순서는 저장 전에 거부한다.
- 서로 다른 프로세스에서 같은 합치기 결과가 같은 바이트가 되도록 pikepdf 저장에 결정론적 문서 ID를
  사용했다. summary.ai가 결과 해시로 재현 여부를 비교할 수 있게 하는 조건이다.
- 합성 3×100쪽 문서와 100쪽 필기 비교를 Edge에서 실제 업로드해 지연 로딩·연속 스크롤을 확인했다.
  드래그 경고에서 취소하면 순서가 유지되고, 계속하면 순서와 영향 행의 확인 상태가 함께 바뀌는 것도
  확인했다.

## 내린 결정과 근거

- summary.ai에는 PDF 합치기를 다시 구현하지 않는다. 실제 결과 바이트와 페이지 순서의 단일 책임을
  NotEditor에 둬야 두 구현이 어긋나지 않는다.
- handoff와 사이드카에는 세션마다 바뀌는 `document_id`를 저장하지 않고 절대경로와 페이지 범위만
  기록한다. NotEditor 실행 때 새 ID로 다시 매핑한다.
- 인계 저장은 지정된 PDF를 먼저 완성한 뒤 사이드카를 기록한다. summary.ai가 절반만 끝난 작업을
  완료로 오인하지 않게 하기 위해서다.
- 로컬 웹은 임의 네트워크 주소가 아니라 `127.0.0.1`에만 바인딩한다. 별도 인증 없이 LAN에 문서 처리
  서버를 노출하지 않기 위해서다.
- 네이티브 `window.confirm` 대신 앱 내부 경고 대화상자를 사용한다. 드래그 영향 범위와 취소·진행
  결과를 동일한 UI 안에서 안정적으로 보여주고 자동 검증할 수 있다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| summary.ai가 원본 변경 뒤 자동 재합치기 | 앞쪽 삽입 등으로 같은 쪽 번호가 다른 내용을 가리킬 수 있어 사용자 확인이 필요하다. |
| 계약 판 1로 표현할 수 없는 교차 문서·역순 편집을 적당히 정렬해 기록 | 화면에서 저장한 PDF와 사이드카가 달라져 재현 근거가 사라진다. |
| 기존 pywebview 앱의 이름만 로컬 웹으로 변경 | 웹 업로드·다운로드 형식이 아니라 네이티브 브리지와 파일 대화상자를 계속 사용한다. |
| 로컬 서버를 Windows 서비스로 상시 실행 | 설치 권한·업데이트·제거 범위가 커지고 사용하지 않을 때도 프로세스가 남는다. |
| 실제 샘플 없이 Goodnotes·Flexcil 지원을 UI에 표시 | 공식 내보내기가 평탄화 PDF일 수 있어 편집 가능한 필기 보존을 보장할 수 없다. |

위 결정들은 세 관련 명세의 `고려했다가 안 한 것`에 이미 기록되어 있다.

## 미해결 질문 / 블로커

- 현재 PC에 Inno Setup의 `iscc.exe`가 없어 설치 EXE 자체는 만들지 못했다. PyInstaller의 두 실행
  파일, Inno 스크립트 계약과 실제 로컬 웹 실행은 검증했다.
- 실제 Samsung Notes·Notewise 앱에서 실물 SDOCX·Notewise를 다시 여는 기기 왕복은 미확인이다.
  구조 보존과 합성 샘플 테스트는 통과했다.
- 오창모 PDF의 실제 파일이 없어 눈에 보이는 슬라이드 기준 자동 정렬 품질은 미확인이다.
- Goodnotes·Flexcil은 편집 가능한 원본 내보내기 샘플이 없어 후순위 조사 상태다.
- 원격 Render 배포에는 이번 커밋을 아직 반영·검증하지 않았다. 이번 범위는 로컬 구현과 패키지였다.

## 다음 단계

1. Inno Setup이 있는 Windows에서 `venv\Scripts\pyinstaller.exe --noconfirm NotEditor.spec` 후
   `iscc.exe installer\NotEditor.iss`를 실행하고, 설치·제거 및 두 바로가기를 실제 확인한다.
2. 실제 summary.ai 화면에서 변경된 원본의 `NotEditor로 확인` 동작을 실행해 패키지
   `NotEditor.exe --open-plan <handoff.json>`을 열고, 저장 뒤 summary.ai가 PDF와 사이드카를 회수하는
   사용자 흐름을 한 번 검증한다.
3. 사용자가 실물 SDOCX·Notewise와 오창모 PDF를 제공하면 원본은 보존한 채 사본으로 필기 이동·페이지
   재정렬을 수행하고 Samsung Notes·Notewise에서 다시 열어 좌표와 편집 가능 여부를 확인한다.
4. Goodnotes·Flexcil 지원을 재개할 때는 각 앱의 편집 가능한 원본 내보내기 샘플부터 확보하고
   `docs/research/2026-08-30-goodnotes-flexcil-support.md`의 판정을 갱신한다.
5. 배포 반영이 필요하면 `main` 푸시 뒤 Render 빌드와 `/api/health`, 실제 PDF/SDOCX 업로드를 별도
   검증한다. 이전 서비스 삭제나 도메인 변경은 별도 승인 없이 하지 않는다.
