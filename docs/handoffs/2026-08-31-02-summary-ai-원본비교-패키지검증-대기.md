# summary.ai 원본 비교 구현 · 패키지 검증 대기 인계

## 현재 상태

NotEditor의 판 2 합치기·원본 비교 구현은 `180a4d3`, README와 명세 갱신은 `6543e47`에 있다.
작업 트리는 깨끗하다. 기존 판 1 계획을 계속 읽으면서 빈 합치기 계획의 수집함 자동 선택, 실제
사용본과 현재 원본의 쪽 비교, 생성 방식별 갱신·넘어가기 결정을 지원한다. 전체 189개 테스트를
통과했고 소스 체크아웃 실제 실행과 교차 저장소 skip 결정 왕복도 통과했다. 최신 PyInstaller 패키지
완주와 화면 검증만 남아 명세 상태는 `패키지 검증 중`이다.

## 이번 세션에 한 일

- 구현 전 별도 명세를 `17c8b56`로 커밋했다.
- 공용 계약 판 2를 읽고 판 1을 하위 호환하는 계획 파서를 구현했다.
- 빈 merge 계획이면 `input_root`에서 PDF 다중 선택창을 자동으로 연다.
- summary.ai 인계 세션에서 `input_root` 밖 파일을 추가·저장하지 못하게 했다.
- review 계획에서 기준 PDF와 모든 현재 PDF 쪽을 기존 `page_match` 지문으로 비교한다.
- 필기 옮기기의 `review-row` 두 열 표현과 문서 합치기의 페이지 선택·범위·순서 UI를 함께 쓴다.
- selected 자료에는 `전체 갱신`/`넘어가기`, merged 자료에는 `합쳐서 갱신`/`넘어가기`만 노출한다.
- 합쳐서 갱신은 PDF와 합치기 사이드카를 먼저 쓴 뒤 결정 파일을 원자적으로 기록한다.
- 기준 PDF는 결과 선택·삭제 대상에서 제외했다.
- README와 활성 명세에 판 2 운영 규칙과 현재 검증 상태를 반영했다.

## 내린 결정과 근거

- 쪽 동일성은 기존 시각 지문·동적 정렬을 재사용한다. 파일 전체 해시는 어느 쪽이 같은지 말해 주지 않는다.
- 비교 기준 문서는 별도 역할로 로드하고 합치기 후보에서 제외한다. 일반 후보로 섞으면 실제 사용본
  페이지가 새 결과에 들어갈 수 있다.
- 결정 허용 범위는 summary.ai가 인계한 `origin`으로 고정한다. UI뿐 아니라 Python API에서도
  selected/merged에 맞지 않는 결정을 거부해 우회 호출도 막는다.
- 경로 제한은 NotEditor와 summary.ai 양쪽에서 검사한다. 한쪽 검증만 믿으면 독립 실행이나 계약
  변경 때 수집함 밖 파일이 들어올 수 있다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 기준 PDF를 일반 합치기 parts에 포함 | 결과 페이지 선택에 섞이는 역할 혼동이 생긴다. |
| summary.ai가 렌더한 이미지 비교 | 페이지 동일성 엔진과 UI가 두 앱에 중복된다. |
| 같은 쪽이면 자동 넘어가기 | 불확실 매칭과 사용자의 갱신 의도를 숨긴다. |
| Drive 경로를 직접 열기 | 로컬 수집함 경계와 입력 Drive 읽기 전용 원칙을 깨뜨린다. |

## 미해결 질문 / 블로커

- 최신 코드의 패키지 검증이 남았다. 기존 `dist\NotEditor\NotEditor.exe`는 코드보다 오래된 빌드다.
- `venv\Scripts\pyinstaller.exe --noconfirm NotEditor.spec`을 시작했지만 사용자 요청으로 Analysis 중
  Ctrl+C 종료했다. `build/`, `dist/`는 추적 대상이 아니며 기존 dist 실행 파일은 남아 있다.
- 소스 체크아웃 `--open-plan` 프로세스는 판 2 빈 merge 계획으로 6초 이상 정상 유지됐고 종료·임시
  폴더 정리까지 했다. 새 패키지의 실제 판 2 화면은 미확인이다.

## 다음 단계

1. `venv\Scripts\pyinstaller.exe --noconfirm NotEditor.spec`을 끝까지 실행한다.
2. 새 `dist\NotEditor\NotEditor.exe --open-plan <판2 빈 merge JSON>`으로 실행해 수집함 시작 경로의
   자동 파일 대화상자를 확인한다.
3. 판 2 review JSON으로 실행해 실제 사용본/현재 원본 두 열, 같은 쪽·다른 쪽 배지, 생성 방식별
   갱신 버튼과 넘어가기를 확인한다.
4. `venv\Scripts\python.exe -m unittest discover -s tests -q`를 다시 실행한다.
5. 명세의 패키지 체크박스를 체크하고 상태를 `완료`로 바꾼 뒤 별도 커밋한다.
