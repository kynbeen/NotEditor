# 웹 상시 가동(UptimeRobot)과 헬스 핑 세션 정리

**날짜:** 2026-08-28
**기기:** LAPTOP
**관련 명세:** `docs/specs/2026-08-26-03-NotEditor-리브랜딩과-데스크톱-웹-배포.md`

## 현재 상태
웹앱이 `https://not-editor.onrender.com` 에 배포돼 있고 정상 응답한다. Render 무료 등급은 15분간
요청이 없으면 서버를 재웠다가 다음 요청에서 다시 깨우는데(이때 수십 초가 걸린다), 이를 막으려고
UptimeRobot(사이트가 살아있는지 주기적으로 확인해 주는 외부 서비스)으로 5분마다 헬스 엔드포인트를
두드리게 했다. 이 주기적 요청이 서버에 쓸모없는 세션을 계속 쌓던 문제는 코드를 고쳐 해결했고,
수정본이 실제 배포까지 반영된 것을 확인했다. UptimeRobot 모니터 등록 자체는 사용자가 직접 마쳤다고
알려왔다(**내가 확인한 것은 아니다** — 계정 접근 권한이 없다). PWA 창 자동 최대화는 조사만 끝냈고
앱 코드로는 불가능하다는 결론이며, 사용자가 "해결"이라고 알려왔으나 어떤 방법을 적용했는지는
**미확인**이다.

## 이번 세션에 한 일
- 배포된 사이트 상태와 핑 대상 엔드포인트를 실측했다. `/api/health` 가 `200` 을 반환하고
  `render.yaml` 의 `healthCheckPath` 와도 일치해, 메인 페이지 대신 이쪽을 핑 대상으로 정했다.
- **헬스 핑이 매번 새 세션을 만들던 문제를 고쳤다.** `noteditor/web.py` 의 미들웨어(모든 HTTP
  요청이 거쳐 가는 공통 처리 구간)가 경로를 가리지 않고 세션을 만들어서, 쿠키를 들고 다니지 않는
  UptimeRobot 요청마다 `ComposerApi` 객체와 임시 디렉터리가 하나씩 생겼다. 5분 주기 · 세션 수명
  1시간이면 항상 12개쯤이 놀고 있는 셈이었다.
- 이 수정을 지키는 테스트를 추가하고, **테스트가 실제로 작동하는지도 확인했다.** 수정을 무효화한
  상태로 돌려 `AssertionError: 'noteditor_session' unexpectedly found` 로 깨지는 것을 봤다.
- 전체 테스트 95개 통과(`python -m unittest discover -s tests`, CI와 같은 명령).
- `a2e07a4` 로 커밋·푸시하고 GitHub Actions 통과(run `33157324616`), Render 자동 배포 반영까지
  확인했다. 배포 확인은 버전 번호가 아니라 **`/api/health` 응답에서 `Set-Cookie` 가 사라지는 것**을
  신호로 썼다(이번 수정이 버전을 올리지 않아 `0.4.0` 그대로였기 때문).
- Render 무료 등급의 월 750 인스턴스 시간이 **워크스페이스(서비스들을 묶는 단위) 단위**임을 문서로
  확인하고, 24시간 가동이 월 약 730시간이라 한도에 근접한다는 점을 알렸다. 사용자가 해당
  워크스페이스에 다른 무료 서비스가 없음을 확인해 주었다.
- PWA 창 자동 최대화 가능 여부를 조사하고 Windows에서 직접 실험했다(아래 "내린 결정과 근거" 참고).

## 내린 결정과 근거
- **핑 대상을 `/` 가 아니라 `/api/health` 로 했다.** 응답이 JSON 한 줄뿐이라 가볍고, `render.yaml`
  이 이미 같은 경로를 헬스체크 경로로 쓰고 있어 의도가 한곳에 모인다. `HEAD` 요청도 지원한다.
- **미들웨어에서 세션을 건너뛰되 만료 정리는 계속 돌게 했다.** 단순히 통과시키기만 하면, 만료된
  세션을 치우는 코드가 `acquire()` 안에만 있어서 정리가 같이 멈춘다. 그러면 진짜 사용자가 올
  때까지 버려진 세션이 남는다. `SessionStore.expire_idle()` 을 따로 빼서 핑이 정리는 계속
  유발하되 새로 만들지는 않도록 했다.
- **면제 경로를 `if`문에 문자열로 박지 않고 `SESSIONLESS_PATHS` 상수로 뒀다.** 앞으로 세션이
  필요 없는 경로가 늘어날 때 한곳만 고치면 된다.
- **`main` 에 바로 커밋했다.** 이 저장소는 머지 커밋 없이 전부 `main` 에 직선으로 쌓아온 방식이고,
  Render 자동 배포도 `main` 을 보고 있어서 브랜치를 파면 배포가 되지 않는다.
- **PWA 최대화는 앱 코드로 못 한다고 결론지었다.** MDN의 웹 앱 매니페스트(PWA 설정 파일) 멤버
  전체 목록을 확인했는데 창 크기·창 상태를 지정하는 항목이 아예 없다. 매니페스트를 고치는
  방향은 가능성이 없다.

## 고려했다가 안 한 것
| 대안 | 왜 안 했나 |
|---|---|
| GitHub Actions 정기 실행(cron)으로 깨우기 | 사용자가 UptimeRobot을 선택했고 이미 등록을 마쳤다. 다만 Render 무료 시간이 빠듯해지면 "낮 시간대만 깨우기"가 필요해질 수 있는데, UptimeRobot 무료 등급에는 시간대 지정이 없어 그때는 이 경로가 다시 후보가 된다. |
| Render 워크스페이스를 여러 개 만들어 무료 시간 늘리기 | 문서에 언급이 없고 사실상 할당량 우회다. 믿고 기댈 근거가 못 된다. |
| 매니페스트 `"display": "fullscreen"` 으로 최대화 흉내 | 데스크톱에서는 대체로 `standalone` 으로 되돌아가고, 동작하더라도 최대화가 아니라 제목표시줄이 사라지는 전체화면이다. |
| `window.resizeTo()` / 로드 시 `requestFullscreen()` | 스크립트가 직접 연 창이 아니면 브라우저가 크기 조정을 무시한다. 전체화면 전환은 사용자 클릭 같은 동작 없이는 거부된다. |
| 배포 확인을 버전 번호로 하기 | 이번 수정이 버전을 올리지 않아 신호가 되지 못했다. 쿠키 유무가 이 수정에서만 생기는 변화라 더 확실했다. |

## 변경한 파일
| 파일 | 무엇을 / 왜 |
|---|---|
| `noteditor/web.py` | `SESSIONLESS_PATHS` 상수 추가, `SessionStore.expire_idle()` 추가, 미들웨어가 면제 경로에서는 세션을 만들지 않고 정리만 하도록 수정. 헬스 핑이 세션을 쌓지 않게 하려고. |
| `tests/test_web.py` | `test_health_ping_creates_no_session` 추가. 헬스를 5번 두드려도 세션 수·쿠키가 그대로이고, `/` 요청에는 세션이 정상 생성되는지 확인. |

## 미해결 질문 / 블로커
- **UptimeRobot 모니터가 실제로 등록·작동 중인지 미확인.** 사용자가 직접 했다고 알려왔으나 계정
  접근 권한이 없어 검증하지 못했다. 며칠 뒤 사이트가 여전히 즉시 응답하는지로 간접 확인할 수 있다.
- **PWA 자동 최대화를 사용자가 어떤 방법으로 해결했는지 미확인.** 조사 결과 유일하게 검증된 방법은
  바로가기에 `--start-maximized` 플래그를 붙이는 것이다. Edge 앱 창으로 실험해 플래그 없이는
  `NORMAL`, 붙이면 `MAXIMIZED` 로 뜨는 것을 Win32 `GetWindowPlacement` 로 확인했다. 다만
  **설치된 PWA 바로가기 형태(`msedge_proxy.exe --app-id=<해시>`)로는 검증하지 못했다** — 이
  기기에 PWA가 설치돼 있지 않다. 시작 메뉴·바탕화면을 훑었을 때 나온 건 데스크톱 앱 바로가기
  하나뿐이었다.
- **"한 번 최대화해두면 브라우저가 기억한다"는 통설은 이 기기 실험에서 재현되지 않았다.** 최대화
  상태로 정상 종료 후 같은 프로필로 다시 열었더니 `NORMAL` 로 떴다. 설치된 PWA에서는 다를 수
  있으나 확인하지 못했다.
- Render 무료 시간 750시간 대비 24시간 가동 약 730시간. 여유가 20시간뿐이라 **다른 무료 서비스를
  같은 워크스페이스에 추가하면 월말 전에 전부 정지된다.** 현재는 NotEditor 하나뿐이다(사용자 확인).

## 다음 단계
바로 착수해야 할 필수 작업은 없다. 세션 목표가 모두 끝났다. 이어서 한다면:
1. 며칠 뒤 `curl -s -o /dev/null -w "%{http_code} %{time_total}\n" https://not-editor.onrender.com/`
   를 재실행해 응답이 1초 안쪽인지 본다. 수십 초가 걸리면 UptimeRobot 핑이 실제로는 안 도는 것이다.
2. Render 대시보드에서 이번 달 인스턴스 시간 사용량을 확인해 750시간 한도에 실제로 얼마나
   근접하는지 실측한다.
3. PWA 최대화를 아직 못 했다면, Edge에서 `https://not-editor.onrender.com` 을 설치한 뒤 시작 메뉴의
   `NotEditor.lnk` 를 열어 `Arguments` 끝에 ` --start-maximized` 를 추가하고 실제로 최대화되는지
   확인한다.
4. 명세에 남은 미검증 항목 두 개(Docker 이미지 실행, 태그 릴리스로 설치 파일 빌드)는 이번 세션에서
   손대지 않았다. 여전히 열려 있다.
