# 원본 검토 UI 단순화 인계

**날짜:** 2026-08-31
**기기:** LAPTOP
**관련 명세:** `docs/specs/2026-08-31-01-summary-ai-합치기-인계.md`, `docs/specs/2026-08-31-02-summary-ai-원본-쪽비교와-수집함-합치기.md`

## 현재 상태

summary.ai의 합치기·자세히 보기 인계 창은 긴 버튼 문구가 한 줄로 유지된다. 원본 자세히 보기는
왼쪽의 큰 실제 사용본/현재 수집함 비교와 오른쪽의 수집함 PDF 쪽 선택으로 구성되며, 오른쪽에서
해제한 쪽은 왼쪽의 현재 수집함 미리보기에서도 어둡게 표시된다. 일반 합치기와 원본 검토의 결과
순서변경 UI는 제거했고, 문서를 추가한 순서와 각 PDF의 원래 쪽 순서를 결과 순서로 사용한다.

## 이번 세션에 한 일

- 합치기 결과 순서 패널과 드래그 순서변경 코드를 제거했다.
- 원본 검토를 큰 왼쪽 비교 영역과 오른쪽 쪽 선택 영역의 2열로 재배치했다.
- 같은 변경, 고른 범위 안 변경, 인접 변경의 색 대비를 강화했다.
- 달라진 쪽 이전/다음 이동과 큰 페이지 미리보기 등 기존 비교 기능을 유지했다.
- 오른쪽에서 쪽·범위·전체를 해제하면 왼쪽의 대응하는 현재 수집함 미리보기만 어둡게 연동했다.
- 넘어가기가 파일을 유지하고 현재 수집함 버전을 원본 최신으로 확인한다는 문구를 명확히 했다.
- 인계 세션의 긴 버튼과 라벨이 여러 줄로 접히지 않게 했다.
- NotEditor 전체 자동 테스트 199개와 JavaScript 문법 검사를 통과했다.

## 내린 결정과 근거

- 한 행에 세 페이지를 넣으면 실제 내용을 읽을 수 없어, 기준/현재 두 페이지를 가능한 크게 보여 준다.
- 쪽 포함 여부는 오른쪽 선택 UI가 단일 책임을 갖고, 왼쪽 비교는 그 상태를 밝기만으로 즉시 반영한다.
- 결과 순서변경은 검토에 필요한 핵심 판단이 아니고 UI와 상태를 복잡하게 하므로 제거했다.
- 넘어가기는 PDF 생성·교체가 아니라 사람의 확인 결정이며, 실제 해시 기준 갱신은 summary.ai가 담당한다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 기준·현재·결과 세 페이지를 한 행에 표시 | 페이지 본문이 너무 작아져 차이를 읽을 수 없었다. |
| 별도 결과 순서 패널과 드래그 유지 | 쪽 선택과 비교를 방해하고 사용자가 기능 제거를 결정했다. |
| 선택 해제한 비교 행 전체를 어둡게 표시 | 실제 사용본까지 흐려지면 비교 근거가 사라지므로 현재 수집함 쪽만 어둡게 했다. |

| `docs/specs/2026-08-31-02-summary-ai-원본-쪽비교와-수집함-합치기.md` | 결과 순서 고정과 새 검토 UI 결정을 반영 |

## 미해결 질문 / 블로커

소스 체크아웃 테스트는 통과했지만 이번 UI 수정 이후 PyInstaller 설치 패키지는 다시 만들지 않았다.

## 다음 단계

1. `venv\Scripts\pyinstaller.exe --noconfirm NotEditor.spec`로 최신 설치 실행본을 다시 만든다.
2. 최신 패키지에서 summary.ai 원본 검토 계획을 열어 오른쪽 쪽 해제가 왼쪽 현재 수집함
   미리보기를 어둡게 하는지 눈으로 확인한다.
3. 넘어가기 후 summary.ai가 최대화 상태로 돌아오고 합치기 원본이 `원본 최신`이 되는지 교차 확인한다.
