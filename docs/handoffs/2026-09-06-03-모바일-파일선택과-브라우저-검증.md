# 모바일 파일 선택과 브라우저 검증 인계

**날짜:** 2026-09-06
**기기:** LAPTOP
**관련 명세:** `docs/specs/2026-08-30-01-NotEditor-안정화와-시각적-쪽-정렬.md`

## 현재 상태

미매칭 필기 보존과 판 3 동기화에 이어, 미완료였던 쪽 이동·목차 입력의 브라우저 검증을 진행했다.
모바일 파일 선택을 막던 실제 CSS 오류를 고쳤고 Edge의 데스크톱·모바일 화면 크기에서 파일 선택,
쪽 이동 확인 대화상자, 빈 원본 자동 생략, 목차 편집·다운로드가 통과했다. 실제 태블릿 앱 검증과
기존 목차 정책·정렬 품질 정책은 여전히 미완료다.

## 이번 세션에 한 일

- Playwright가 390px 화면에서 파일 선택 버튼을 클릭할 때 `.transfer-arrow`가 포인터를
  가로챈다는 오류를 재현했다. 전체 너비로 늘어난 요소를 90도 회전한 것이 원인이었다.
- 화살표를 30×30px 고정 영역에 가운데 배치하고 포인터 이벤트를 받지 않게 했다.
- PWA 셸 캐시를 v12로 올렸다.
- 로컬 Edge를 Playwright로 실행해 1440×1000·390×844에서 파일 선택창을 통해 합성 SDOCX와
  대상 PDF를 올렸다. 빈 원본 1쪽 생략, 별도 노트 1쪽 포함, 결과 4쪽을 확인했다.
- 쪽 이동 취소 시 계획 유지, 수락 시 대응 변경과 재확인 필요, 행 확인까지 실제 버튼으로 검사했다.
- 모든 검토 이미지의 로딩 성공, 페이지 JavaScript 오류 없음, 가로 넘침 없음을 검사하고
  대화상자·검토 화면·목차 화면 스크린샷을 확인했다.
- 실제 Goodnotes fixture와 그 배경 PDF를 업로드하고 JSON 파일 선택 후 제목을 편집했다.
  다운로드한 결과를 다시 읽어 편집된 제목이 결과 1쪽 UUID에 연결됨을 두 화면 크기에서 검증했다.
- 관련 단위·Node·정적 UI 54개 통과. Android `testDebugUnitTest assembleDebug` 성공.

## 내린 결정과 근거

- 모바일 파일 선택 오류는 레이아웃과 포인터 처리 두 속성으로 해결했다. 별도 이벤트 우회나
  강제 클릭 없이 실제 사용자의 버튼 클릭이 통과한다.
- 브라우저 목차 저장과 Goodnotes 앱 내 목차 이동은 서로 다른 검증이다. 백로그를 분리해
  다운로드 파일 검증이 실제 앱 왕복까지 증명하는 것으로 읽히지 않게 했다.

## 고려했다가 안 한 것
