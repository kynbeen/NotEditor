# 미매칭 필기 보존과 검토 계약 인계

**날짜:** 2026-09-06
**기기:** LAPTOP
**관련 명세:** `docs/specs/2026-08-30-01-NotEditor-안정화와-시각적-쪽-정렬.md`, `docs/specs/2026-08-31-02-summary-ai-원본-쪽비교와-수집함-합치기.md`

## 현재 상태

기능 체크포인트 `725c77a`까지 새 PDF에 매칭되지 않은 기존 필기 쪽을 추정 위치에 끼워 넣어
미리보기와 저장본에 보존한다. SDOCX의 PDF 외 별도 노트 쪽도 원본 순서에 맞춰 검토 화면에
표시하고 원본 페이지 바이트를 저장한다. 원본 검토 결정은 파일 교체 방식과 변경 종류를 분리한
판 3 구조로 확장했으나, `C:\dev\summary.ai`와 공용 workspace 계약의 판 3 동기화는 아직 하지 않았다.

## 이번 세션에 한 일

- SDOCX·Notewise·Goodnotes에서 새 PDF에 없는 기존 PDF 쪽의 배경과 필기를 결과 열에도 렌더링하고,
  자동 매칭 순서대로 저장하도록 연결했다.
- SDOCX 별도 노트 쪽을 `pageIdInfo.dat` 원본 순서로 읽어 가장 가까운 보존 앞쪽 다음에 배치했다.
  단색 배경과 필기는 미리보기로 표시하고 페이지 파일은 바이트 단위로 보존했다.
- 데스크톱, 로컬 웹, Android의 공통 필기 미리보기 호출에 별도 노트 쪽 ID를 연결했다.
- 원본 검토에서 파일 교체 방식(`refresh`/`merge`/`skip`)과 변경 종류
  (`none`/`questions`/`content`/`both`)를 분리하고 변경 쪽 번호를 결정 파일에 기록하도록 확장했다.
- 강의록 시각 지문으로 족첵 안의 강의 범위를 제안하는 `noteditor/exam_range.py`와 UI 진입점을 추가했다.
- 합성 SDOCX를 로컬 웹에 올려 `원본 1 -> 원본 2 -> 별도 노트 3 -> 미매칭 원본 3 -> 원본 4`
  순서와 별도 노트 필기 1획 렌더링을 Edge에서 확인했다.
- Python 전체 테스트 297개, JavaScript 구문 검사, Android `testDebugUnitTest assembleDebug`를 통과했다.

## 내린 결정과 근거

- 미매칭 기존 쪽은 새 PDF에서 빠졌다는 이유로 버리지 않는다. 필기가 있으면 사용자의 작업물이므로
  기존 배경과 함께 가장 자연스러운 자동 매칭 위치에 남긴다.
- SDOCX 별도 노트는 PDF 쪽 번호 체계에 억지로 넣지 않는다. 세 형식이 공유하는 `PagePlan` 계약을
  유지하면서 SDOCX에만 있는 원본 순서 메타데이터로 표시·배치한다.
- 해석하지 못한 템플릿·이미지 배경을 단색으로 가장하지 않는다. 미리보기 제한을 알리고 저장 시
  페이지와 관련 리소스를 원본 그대로 보존하는 편이 실제 결과와의 정합성을 지킨다.
- summary.ai 자유 순서는 현재 판 1·2 재현 규격이 연속 오름차순 범위를 전제로 하므로 즉시 열지 않았다.
  유지보수상 이득을 판단하려면 판 3 계약 소비자까지 함께 고친 뒤 교차 저장·재현을 검증해야 한다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 별도 노트 쪽을 일반 PDF 원본 인덱스로 취급 | 내장 PDF 쪽 인덱스라는 기존 공통 계약과 충돌한다. |
| 템플릿·이미지 배경을 흰색으로 대체해 미리보기 | 저장 결과와 다른 화면을 보여 주므로 사용자 검토를 오도한다. |
| 미매칭 쪽을 새 PDF에 없다는 이유로 제외 | 사용자가 명시적으로 보존을 요구했고 필기 손실을 만든다. |

## 미해결 질문 / 블로커

- Goodnotes 원본 목차와 입력 JSON 목차를 병합할지 교체할지 사용자 답변이 필요하다.
- SDOCX 템플릿·이미지 배경 미리보기는 해당 리소스가 포함된 실제 샘플이 필요하다.
- Goodnotes, Samsung Notes, Notewise 결과의 실제 앱 편집 왕복과 Android 실제 기기 검증은 장비가 필요하다.
- 족첵 범위 자동 인식은 모듈과 UI가 있으나 전용 합성·실물 회귀 테스트가 아직 없다.
- NotEditor 판 3 결정은 summary.ai 및 공용 workspace 계약 소비자와 아직 동기화되지 않았다.
