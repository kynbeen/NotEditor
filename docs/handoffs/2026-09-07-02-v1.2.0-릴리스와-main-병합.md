# v1.2.0 릴리스와 main 병합

**날짜:** 2026-09-07
**기기:** LAPTOP
**태그:** `v1.2.0`
**관련 명세:** `docs/specs/2026-08-30-01-NotEditor-안정화와-시각적-쪽-정렬.md`, `docs/specs/2026-09-02-01-PDF-기준-필기-페이지-비율.md`

## 현재 상태

`feat/outline-pypdf-and-review-reorder` 브랜치를 `main` 브랜치에 병합하고, 새 릴리스 태그 `v1.2.0`을 생성하여 원격(`origin`)에 푸시했다.
GitHub Actions에서 Windows 설치 프로그램 빌드(`windows-release`), Android 빌드(`android-build`), 전체 테스트(`test`)가 트리거되어 릴리스 배포가 진행 중이다.
로컬 작업 트리는 깨끗하며, 사용자가 남겨둔 질문 답변 문서(`codex 질문에 대한 답변.md`)는 미커밋 상태로 안전하게 보존되었다.

## 이번 세션에 한 일

- **배포 전 무결성 검증**:
  - Python 단위·통합 테스트 303개 전체 실행 및 통과 확인 (`unittest discover -s tests`).
  - 프론트엔드 JavaScript 문법 검사 통과 (`node --check noteditor/static/app.js`).
  - Android JVM 단위 테스트 및 Python-Android 연동 테스트 통과 (`./gradlew testDebugUnitTest`).
  - Android Debug APK 빌드 통과 (`./gradlew assembleDebug` -> `app-debug.apk` 44.9MB 생성).
  - Windows PyInstaller 패키징 빌드 통과 (`pyinstaller --noconfirm NotEditor.spec` -> `NotEditor.exe`, `NotEditorLocalWeb.exe` 생성).
- **브랜치 병합 및 릴리스**:
  - 미커밋 파일(`codex 질문에 대한 답변.md`)을 `git stash`로 안전 보관.
  - `main` 브랜치로 전환 및 최신 상태 동기화 확인.
  - `feat/outline-pypdf-and-review-reorder` 브랜치를 `main`에 병합(Merge commit 생성).
  - 임시 보관했던 `codex 질문에 대한 답변.md` 복원(미커밋 상태 유지).
  - 릴리스 버전 태그 `v1.2.0` 생성.
  - `main` 브랜치 및 `v1.2.0` 태그를 `origin`에 푸시하여 GitHub Actions 자동 릴리스 빌드 파이프라인 트리거.

## 이번 릴리스(v1.2.0) 주요 반영 사항

1. **Goodnotes 6 필기 이전 지원**:
   - `.goodnotes` ZIP/Protobuf 구조 파싱 및 펜·형광펜 스트로크 렌더링 지원.
   - 사용자 결정에 따라 목차 JSON 입력/생성 기능은 제거하고, 원본 목차 손실 방지 안전 검사 유지.
2. **필기 대상 쪽 수동 재정렬 및 검토 UI 개편**:
   - 좌우 비교 검토 화면에서 대상 쪽의 드래그 및 위·아래 이동 버튼 제공.
   - 미매칭 필기 보존(새 PDF에 없는 기존 필기 쪽 결과 포함).
3. **정렬 품질 정책 적용**:
   - 가로·세로 배율 불일치, 잔차 50mm 초과, 경계 이탈 5mm 이상 시 모든 대응 쪽을 주황색 '확인 필요'로 표시.
   - 명시적 사용자 승인 후 저장하도록 안전장치 마련.
4. **Android 기본 렌더링 및 조립 지원 강화**:
   - 플랫폼 `PdfRenderer` 및 `pypdf` 기반 PDF 조립 지원, 회전·CropBox 보존.

## 내린 결정과 근거

- **미커밋 질문 문서 보존**: 사용자의 명시적 요청("미커밋 파일은 빼고")에 따라 stash 후 병합을 수행하고 다시 복원하여 커밋에 포함하지 않고 작업 트리에 보존했다.
- **버전 태그를 v1.2.0으로 결정**: Goodnotes 6 지원, 행 기반 재정렬 UI, 정렬 품질 정책 등 주요 기능이 대거 추가되었으므로 마이너 버전을 올리는 시맨틱 버저닝 규칙에 따라 `v1.2.0`으로 태깅했다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 질문 답변 문서를 릴리스 커밋에 포함 | 사용자가 명시적으로 "미커밋 파일은 빼고"라고 지시함 |
| 로컬 Inno Setup으로 설치파일 수동 빌드 | 로컬 환경에 Inno Setup 컴파일러가 없으며, CI에서 자동 빌드되도록 워크플로가 이미 완비되어 있음 |
